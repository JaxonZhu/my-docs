# EgoWAM 论文解读：人类数据迁移中的未来表征选择

论文原题：EgoWAM: World Action Models Beyond Pixels with In-the-Wild Egocentric Human Data

- 作者：Baoyu Li、Xinchen Yin、Mengying Lin、Yixin Zhang、Danfei Xu
- 团队：Georgia Institute of Technology
- 论文：[arXiv:2607.08436v1](https://arxiv.org/abs/2607.08436v1)，2026 年 7 月 8 日提交
- 项目与演示：[EgoWAM](https://gatech-rl2.github.io/egowam.github.io/)
- 代码：[GaTech-RL2/EgoWAM](https://github.com/GaTech-RL2/EgoWAM)
- 数据：[EgoVerse 数据浏览器](https://partners.mecka.ai/egoverse?task=EgoWAM_fold_clothes)

EgoWAM 研究一个具体问题：**把自然采集的人类第一视角数据加入机器人训练时，预测什么样的未来，才能帮助模型迁移物体、场景和操作信息？** 作者固定策略骨干、动作头和数据组合，比较三类辅助预测目标：像素 VAE 潜变量、DINO 特征和经过相机运动补偿的 3D 运动场。

实验中的两种抽象表征各有优势：DINO 更有利于新物体与新场景泛化，3D Flow 更有利于训练场景内不同空间布局下的精细操作。像素预测的迁移收益相对不稳定，画面更清晰也不一定意味着动作更可靠。这里的结论来自三项双臂任务，且每项任务单独训练策略。

我最关注的是它对世界模型用途的拆分：**未来预测在训练时塑造共享表征，部署时只运行动作策略。** EgoWAM 不需要在每次控制时生成未来视频，再根据视频搜索动作。下文的方法、数字和原论文配图均采用 v1。

## 一、先把动作对齐，再研究世界监督

### 1.1 同一任务在人和机器人上未必具有同样动作

人可以侧着握住杯子再转腕，平行夹爪却可能需要从另一个方向接近；人采集视频时会低头或转头，机器人头部相机则通常固定。即使任务目标相同，直接模仿人的动作也可能得到机器人难以执行的轨迹。

EgoWAM 先建立经过动作对齐的行为克隆（BC）基线，再增加世界预测通道。两者都保留人类动作监督；世界监督为共享骨干增加了一种学习任务变化的方式，而非简单丢弃全部人类动作标签。（论文 §3）

### 1.2 统一到当前相机下的 14 维动作空间

每条臂使用 6 维末端位姿加 1 维夹爪状态，双臂合计 14 维。机器人关节指令通过正运动学转换为末端位姿，再变换到固定的头部相机坐标系；人类手部位姿则需要消除采集者头部运动的影响。

若 $T_t$ 表示时刻 $t$ 的设备坐标系到世界坐标系的变换，$P_{t+i}$ 是未来时刻在设备坐标系中的手部位姿，将整段动作统一到当前设备坐标系，可以写成：

$$
\widetilde P_{t+i}=T_t^{-1}T_{t+i}P_{t+i}.
$$

这只是坐标统一，不能消除手与夹爪的形态差异，也不能保证人的抓取策略可由机器人实现。

作者还处理了速度与工作空间范围：人类动作窗口为 1.0 秒，机器人为 1.5 秒，分别从 30 帧、45 帧重采样到同样的 $k=100$ 个动作时间点；各动作维度的第 1、99 百分位映射到 $[-1,1]$，降低手部跟踪异常值的影响。（论文 §3.1、附录 B、C）

**100 是重采样后的动作块长度**，不表示机器人以 100 Hz 控制，也不代表人和机器人使用相同的原始时间跨度。

## 二、共享骨干接两个预测头

### 2.1 HPT 负责融合模态与本体

EgoWAM 基于 Heterogeneous Pretrained Transformer（HPT）结构。第一视角视觉 stem 在人和机器人之间共享；机器人样本额外提供手腕视角，末端位姿由本体对应的 MLP 编码。视觉与本体状态 token 一起进入共享 Transformer。

骨干中有两组可学习查询：action tokens 提供动作预测上下文，future tokens 提供未来预测上下文。动作头与世界头读取同一个共享骨干的表示，训练损失都回传到骨干。（论文 §4.1）

论文式 2 将两个读出写为：

$$
\begin{aligned}
z_t &= f_\phi(o_t),\\
p(a,s\mid o_t)&=p_\theta(a\mid z_t)\,p_\psi(s\mid z_t).
\end{aligned}
$$

这里 $a$ 是动作块，$s$ 是未来世界目标。两个头通过共享骨干一起学习；这个表达没有要求先采样动作、把候选动作输入世界模型，再进行规划搜索。

### 2.2 联合损失保留人和机器人的动作监督

完整训练目标是：

$$
\begin{aligned}
\mathcal L_{\mathrm{EgoWAM}}
={}&\mathcal L_{\mathrm{action}}^{R}
+\mathcal L_{\mathrm{action}}^{H}\\
&+\lambda\left(
\mathcal L_{\mathrm{world}}^{R}
+\mathcal L_{\mathrm{world}}^{H}\right),
\qquad \lambda=1.
\end{aligned}
$$

动作头采用条件流匹配：将高斯噪声与真实动作块插值，再结合骨干上下文学习去噪。其解码器有 6 个 block、128 维隐藏状态、4 个注意力头，论文设置为 50 步采样。

| 公共设置 | 论文配置 |
| --- | --- |
| Transformer 骨干 | 256 维、16 blocks、8 heads |
| 骨干查询 | 64 个 action tokens；WAM 额外使用 16 个 future tokens |
| 观测历史 | 1 帧 |
| 表 2 中的视觉 stem | ResNet-18，输出 256 维 |
| 动作块 | $100\times14$ |
| 联合训练批次 | 每步 32 条机器人样本 + 32 条人类样本 |
| 优化器 | AdamW，学习率与 weight decay 均为 $10^{-4}$ |
| 世界损失权重 | 1.0 |

骨干内的 64 个 action query tokens 与解码器输出的 100 步动作块是不同概念。类似地，“DINO 版本”主要指**未来预测目标**采用 DINO 特征，不应由此推断所有输入视觉编码器都换成了 DINO。（附录 B、表 2）

### 2.3 部署时移除世界预测头

执行时只需要当前观测、共享骨干与动作头，世界头不参与推理。作者报告策略在单张 RTX 4090 上以 30 Hz 运行，与 ARX5 控制频率一致。因此，不同世界表征的测试差异主要体现它们在训练阶段如何改变策略表征，而不是测试时生成未来视频的额外计算。（论文 §4.3、附录 B.3）

这与 [Fast-WAM](FastWAM-paper.md) 关于训练监督和未来想象的区分相呼应。EgoWAM 进一步追问：当监督来自人和机器人两个本体时，未来目标应保留哪些信息？

## 三、像素、DINO 和 3D Flow 分别要求模型学习什么？

作者提出三个设计目标：减少无关外观细节，保留跨本体相近的物理效果，以及分离相机运动和环境变化。这些是用于组织实验的假设，不代表某种表征已经完全消除了所有本体差异。

| 世界目标 | 监督内容 | 配套预测头 | 主要保留与局限 |
| --- | --- | --- | --- |
| Pixel | 未来第一视角图像的 Wan VAE 潜变量 | 从零训练的小型 DiT | 保留外观细节，也保留相机变化和本体外观差异 |
| Pixel-PT | 与 Pixel 相同的 VAE 目标 | 预训练的 1.3B 级视频 Transformer | 增加视频先验，但先验也可能与当前物理状态冲突 |
| DINO | 未来图像的 DINOv2-B patch 特征 | RAE 风格 DiT 加宽 DDT 头 | 更抽象的语义与形状信息；仍按图像网格索引 |
| 3D Flow | 在当前相机坐标系中的三维点位移 | 条件流匹配解码器 | 突出空间运动并补偿相机变化；依赖跟踪与位姿估计 |

### 3.1 Pixel 预测 VAE 潜变量，DINO 预测语义特征

Pixel 目标来自冻结的 Wan VAE，将未来 128×128 图像编码为 $16\times16\times16$ 潜变量。Pixel 使用 6 层、384 维的 DiT；Pixel-PT 使用 30 层、1536 维的预训练视频 Transformer。两者不只是初始化不同，容量也有明显差异。

DINO 目标来自冻结的 DINOv2-B：去除 CLS 与 register tokens，对每个 patch 特征做 LayerNorm，得到 $16\times16$ 个 768 维 token。RAE 的像素解码器仅用于可视化；EgoWAM 的监督直接发生在特征空间，不依靠解码后的 RGB 图像计算损失。（论文 §4.2、附录 B.2）

DINO 抽象了部分纹理和外观变化，但 patch 仍固定在图像网格上。人一转头，同一物体就可能出现在不同网格位置，因此语义特征本身没有显式完成相机运动补偿。

### 3.2 3D Flow 把物体运动与转头造成的表观运动分开

论文使用 Track4World 生成三维点运动目标，并利用 Aria 的视觉惯性里程计位姿进行稳定化。为明确坐标含义，令 $x_j^{c_j}$ 表示一个被跟踪点在时刻 $j$ 的相机坐标，$T_j$ 将该相机坐标映射到世界坐标，则在当前相机坐标系中计算位移可写为：

$$
\begin{aligned}
\widetilde x_{t+i}^{c_t}&=T_t^{-1}T_{t+i}x_{t+i}^{c_{t+i}},\\
F_{t\rightarrow t+i}&=\widetilde x_{t+i}^{c_t}-x_t^{c_t}.
\end{aligned}
$$

上式对点的变换按齐次坐标理解。将两个位置变换到同一个坐标系再相减，静止背景的位移应接近零，而正在搬动的物体保留实际位移。固定机器人头部相机的相对变换为单位变换。（论文 §4.2、附录 B.2）

实现使用 28×40 的固定锚点网格，共 1,120 个点；预测整个 100 步窗口的三维位移，目标形状为 $100\times1120\times3$。为抑制噪声，作者按位移阈值过滤锚点：机器人轨迹阈值为 2 mm，人类为 10 mm，并跳过每段人类视频首尾各 20 帧。

**我的理解**：这种目标对像素外观的依赖更弱，但质量仍受三维跟踪、标定和相机位姿误差影响。人的手与机器人夹爪也可能产生不同的遮挡和运动区域；“几何表征”并不自动等于完全本体无关。

### 3.3 这是目标与预测头的配套比较

实验固定共享策略骨干、动作头和数据组合，同时替换世界目标与适合它的预测头。不同目标的维度、时域密度和解码器容量均有差异，因此结论应理解为这几组可运行设计之间的比较。

训练预算也需区分：除 Pixel-PT 外，每方法每任务用单张 L40S 训练 2,000 epochs，每 epoch 100 steps；Pixel-PT 用两张 L40S 训练 1,000 epochs。作者报告各配置耗时约两天，但墙钟时间接近不意味着参数量、优化步数或总算力严格匹配。（附录 B.3）

## 四、人类数据规模与真机评测协议

### 4.1 三类数据怎样混合？

机器人平台为两条六自由度 ARX5 机械臂、平行夹爪、头部 Project Aria 和两个手腕 RealSense D405 相机。机器人示范通过 Meta Quest 3 遥操作采集；人类示范则用 Aria 获取第一视角视频、手部位姿与头部位姿。

### 4.2 成功率与子任务得分是两种指标

| 任务 | 子任务计分 | 完整成功要求 |
| --- | --- | --- |
| 杯子放到托碟上 | 旋转并抓杯、双臂交接、放上托碟，共 3 分 | 杯子正确直立放到托碟上 |
| 三折 T 恤 | 三个折叠阶段各 1 分，共 3 分 | 三个阶段都完整完成 |
| 装购物袋 | 开袋 1 分，每装入一件物品 1 分，共 4 分 | 按规定从左到右的顺序装入三件物品 |

Normalized score 记录平均完成了多少子任务，成功率只统计完整任务。因此，部分步骤变好可以提高 score，却未必提高完整成功率。

按作者给出的主评测协议，每种方法在每项任务上做 20 次 ID rollout 和 20 次 OOD rollout。ID 保留训练场景和物体，随机初始位置与姿态；OOD 分为 10 次新物体、原场景，以及 10 次原物体、新场景，后者改变背景和桌面高度。作者报告共 1,800 次真机 rollout。（论文 §5.1、附录 C.3）

这里的 OOD 物体和 OOD 场景是分别测试；不能写成所有 OOD 试次都同时更换物体与场景。每个任务单独训练一个策略，也不能将三任务结果理解成一个统一多任务模型的能力。

### 5.1 人类数据不一定通过动作监督带来收益

在杯子放置与折衣任务上，作者观察到部分 BC 联合训练设置产生负迁移：策略学到机器人难以执行的人类动作，或仍然过拟合机器人场景。购物袋任务的人机拿放动作较自然地对齐，BC 则能从人类数据中获益。因此，结论是**迁移依赖动作与场景条件**，不能概括成行为克隆无法利用人类数据。（论文 §5.2）

增加世界预测通道后，同一批人类数据还可以通过未来状态损失影响共享骨干。DINO 与 3D Flow 在作者测试的多个设置中获得较大收益，但两者的优势方向不同。

### 5.2 DINO 偏向物体与场景，3D Flow 偏向空间操作

下表选取图 3 中的几组结果，均比较**同一种方法的仅机器人训练与加入 EgoVerse**，成功率单位为百分比。

| 方法与评测 | 仅机器人 | 加入 EgoVerse | 变化 |
| --- | ---: | ---: | ---: |
| BC，杯子 ID | 25% | 15% | −10 个百分点 |
| 3D Flow，杯子 ID | 70% | 90% | +20 个百分点 |
| 3D Flow，装袋 ID | 60% | 90% | +30 个百分点 |
| 3D Flow，折衣 ID | 100% | 100% | 无变化 |
| BC，折衣 OOD | 5% | 0% | −5 个百分点 |
| DINO，折衣 OOD | 15% | 85% | +70 个百分点 |

3D Flow 在杯子与装袋的 ID 操作中获得明显提升，但已到 100% 的折衣 ID 没有继续提高。DINO 的 OOD 优势在折衣任务尤其突出；它也不是所有 OOD 指标都最高。例如，加入 EgoVerse 后，装袋 OOD 的成功率为 3D Flow 55%、DINO 50%，而子任务得分则是 DINO 更高。（论文图 3；数值对照[作者交互图表](https://gatech-rl2.github.io/egowam.github.io/)）

论文摘要的“最高 4 倍”没有明确限定为统一的成功率比较。主图中的成功率增益标注应按**百分点差**解读；归一化得分的差值则是在 0–1 得分尺度上的变化，不能直接当作相对增长率。

## 六、两组对齐实验与监督模态消融

### 6.1 刻意不对齐动作会怎样？

购物袋原本是 BC 能从人类数据获益的任务。作者额外采集一组刻意使用不适合平行夹爪的抓取方式、且视角不同的人类示范，作为反事实对照。BC 与 3D Flow 的变化如下：

| 方法 | 仅机器人基线 | 自然域内人类数据 | 刻意不对齐的人类数据 |
| --- | ---: | ---: | ---: |
| BC | 40% | 45% | 20% |
| 3D Flow | 60% | 80% | 75% |

BC 跌到自身仅机器人基线以下，3D Flow 联合训练仍保留收益。这个比较既要看联合训练的绝对结果，也要注意两种方法的机器人基线原本不同。（论文 §5.2、图 8）

```{figure} https://pic1.imgdb.cn/i/034cezVTuwTHB0MkxKatOq.png
:target: https://pic1.imgdb.cn/i/034cezVTuwTHB0MkxKatOq.png
:alt: 购物袋任务中域内与刻意不对齐人类示范的对照，比较行为克隆和 3D Flow 的成功率及各自机器人基线
:width: 100%
:align: center

**原论文图 8：刻意不对齐的人类数据**。这组实验检验两种训练方式对执行差异的敏感性，不代表已经覆盖任意形式的人类动作噪声。
```

### 6.2 让人刻意模仿机器人，又会怎样？

另一端的消融使用杯子放置任务，让人主动匹配机器人的动作策略、相机高度与静态视角。两种人类数据规模都保持 1:1。

| 方法 | 自然域内人类示范 | 刻意对齐的人类示范 |
| --- | ---: | ---: |
| BC | 15% | 35% |
| Pixel | 35% | 65% |
| DINO | 50% | 70% |
| 3D Flow | 85% | 85% |

BC 的仅机器人基线在这组图中为 25%；刻意对齐后，BC 从低于基线变成高于基线。Pixel 与 DINO 也分别提高 30、20 个百分点，3D Flow 在两种条件下均为 85%。（附录 A.1、图 9）

作者据此强调相机运动补偿的重要性。**我的理解**：采集时同时调整了动作策略、相机高度与视角，因此这组实验支持“对齐方式会改变迁移收益”，但不能把全部变化严格归因于头部运动这一个变量。

### 6.3 只有世界监督是否足够？

作者在杯子放置任务上比较 Action Only、3D Flow Only、Action + 3D Flow，检验人类示范中的动作标签和未来运动监督各自有什么作用。结合论文式 3 与附录 A.2，三种设置的损失项可以整理为：

| 设置 | 人类批次的预测损失 | 机器人批次的预测损失 |
| --- | --- | --- |
| **Action Only** | 动作 | 动作 |
| **3D Flow Only** | 3D Flow | 动作 + 3D Flow |
| **Action + 3D Flow** | 动作 + 3D Flow | 动作 + 3D Flow |

**Action Only 是 BC 联合训练基线**：人类和机器人都只提供动作监督，不训练世界预测头。具体目标是经过坐标对齐、时间重采样和归一化的双臂动作序列，每步 14 维、每块 100 步；共享动作头通过条件流匹配学习预测这些动作。因此，这里的 Action Only 不能理解为“仅关闭人类的世界损失，但保留机器人的世界损失”。

**3D Flow Only 保留完整的机器人监督，只移除人类批次的动作监督**。人类视频仍作为训练数据：用 Track4World 提取场景点的三维运动，并结合 Aria VIO 位姿补偿相机运动，得到当前相机坐标系下的未来位移轨迹；3D Flow 头以这些轨迹为目标进行条件流匹配训练，预测 1120 个采样点在 100 个时间步上的三维位移。该损失更新世界预测头与共享骨干，使人类示范通过场景运动改善策略表征；动作头仍由机器人动作标签训练。因此，Flow Only 既不是丢弃人类数据，也不是让整个机器人策略停止学习动作。

**Action + 3D Flow 是完整 EgoWAM**：人类和机器人批次都同时计算上述两种损失，世界损失权重为 1。两种监督共同更新共享骨干；部署时仍只运行动作预测分支，移除世界预测头。这里的 3D Flow 指场景点的三维位移目标，而条件流匹配是训练预测头的方法，动作头也使用条件流匹配。（[论文 §3.1、§4.3、附录 A.2 与 B.2](https://arxiv.org/html/2607.08436v1)）

```{figure} https://pic1.imgdb.cn/i/034cezb4GGKpWj3t6UbyX0.png
:target: https://pic1.imgdb.cn/i/034cezb4GGKpWj3t6UbyX0.png
```

## 八、跨机器人仿真与结论边界

### 8.1 RoboTwin 中的补充实验

作者在 RoboTwin 2.0 中，以 aloha-agilex 为目标本体，将 arx-x5、franka、ur5 加入联合训练。各本体都映射到同样的双臂 14 维末端动作空间，通过相同 IK 执行接口评估，每个方法使用 100 个相同的保留测试种子。

下表为成功率，单元格按“仅目标本体训练 → 四本体联合训练”列出，单位为百分比。

| 任务 | BC | Pixel | DINO | 3D Flow |
| --- | ---: | ---: | ---: | ---: |
| 抓取不同瓶子 | 2 → 6 | 7 → 11 | 4 → 28 | 0 → 16 |
| 叠三个碗 | 0 → 0 | 0 → 0 | 0 → 8 | 0 → 16 |
| 挂杯子 | 0 → 0 | 0 → 1 | 0 → 0 | 0 → 0 |

作为同动作空间参照，ACT-EE 与 DP-EE 在抓瓶任务上分别为 2%、5%，其余两项均为 0%。跨本体联合训练在抓瓶和叠碗上更有帮助，但不同世界表征仍存在任务差异。（附录表 4）

叠碗任务还包含一个特殊条件：发布的演示数据与当前仿真器中的碗材质发生变化，而位置和几何不变，因此它同时是一次外观偏移测试。精细挂杯任务中所有方法都不超过 1%，说明表征迁移收益没有解决全部精确操作问题。（附录 D）

这些是特定设置下的机器人到机器人补充实验，不能与前面的三项真机人机迁移结果合并成一个整体成功率。

### 8.2 目前改善的是上下文泛化

论文明确指出，主要收益仍是空间、物体和场景等上下文变化下的泛化。它没有证明仅靠人类视频就能学到机器人数据中从未出现的新动作原语；例如，从折 T 恤直接迁移到折短裤，仍超出当前验证范围。

另外，实验为每个任务训练独立策略，大规模多任务联合训练尚待研究。DINO 与 3D Flow 各有优势，当前证据也不足以认定某一种表征在所有任务、规模与本体上都最优。（论文 §7）

**我的理解**：EgoWAM 的价值在于把“增加人类数据”拆成可检查的设计问题：动作是否能对齐，世界目标是否过度关注外观，相机运动是否被剥离，以及监督最终改善了哪一类泛化。与 [OpenWAM](OpenWAM-paper.md) 对照时，前者更聚焦人机迁移的未来表征，后者更关注世界动作模型的结构选择与预训练配方；两者都提示，增加一种监督之前，需要明确它向共享模型传递了什么信息。

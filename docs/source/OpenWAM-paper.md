# OpenWAM 论文解读：用受控实验寻找世界动作模型的预训练配方

论文原题：OpenWAM: An Open, Modular Exploration Towards Systematic World–Action Model Pretraining

- 作者：Yuran Wang、Siqiao Huang、Mingleyang Li、Chenhao Zhang、Jiaqi Liang 等
- 团队：新加坡国立大学、清华大学、北京大学等
- 论文：[arXiv:2609.07398](https://arxiv.org/abs/2609.07398)，本文阅读版本为 2026 年 9 月 7 日的 v1
- 项目：[OpenWAM 官方项目页](https://openwam-official.github.io/)
- 代码：[OpenWAM-Official/OpenWAM](https://github.com/OpenWAM-Official/OpenWAM)
- 模型与资源：[Hugging Face / OpenWAM](https://huggingface.co/OpenWAM)

OpenWAM 关注的问题是：**把视频生成模型变成机器人策略时，哪些结构选择有效，哪些结论会在具身预训练之后改变？** 作者先搭建模块化框架，再逐项比较视频骨干、视觉表征、世界与动作的交互方式、去噪时序及数据组成，最后据此训练 OpenWAM-α。

这篇论文最有价值的部分，是把一些常被打包在一起的设计拆开检验。例如，在未进行具身预训练的实验中，单向交互方案的效果更好：<font color=blue>动作分支通过注意力机制读取未来视频特征，视频分支则不读取动作特征</font>。经过具身预训练后，<u>双向交互方案略有优势</u>。又如，600 小时预训练实验中，主要收益出现在<u>分布外评测</u>，而不是训练分布内。

:::{note}
**阅读范围**：本文依据 [论文 v1](https://arxiv.org/pdf/2609.07398v1)，属于论文解读，未自行复现训练或成功率，也未进行逐行源码核验。下文实验数字均为作者报告值；“最佳”限定在对应实验或论文完整对比表内。配图裁剪自原论文，可点击打开原图。

## 一、先区分框架、研究和最终模型

OpenWAM 包含三个层次，读论文时需要分别理解：

| 层次 | 解决什么问题 | 应该如何使用其结论 |
| --- | --- | --- |
| OpenWAM-Infra | 将模型、训练、服务和评测模块化 | 为替换组件、统一接口和复现实验提供基础 |
| OpenWAM-Study | 在受控设置下逐项检验设计选择 | 得到有条件的经验规律，而非通用最优配置 |
| OpenWAM-α | 汇总研究结果，扩大数据和训练规模 | 用下游微调后的仿真与真机评测验证最终配方 |

WAM 的重要出发点，是利用视频生成模型已经学到的视觉、运动和时序先验。与从视觉语言模型出发的 VLA 相比，这条路线强调对<u>动态世界的建模</u>；但使用视频骨干，并不自动保证更好的控制效果。视觉特征能否被紧凑地建模、动作能读取哪些信息、数据是否覆盖评测分布，都会改变结果。

Infra 将模型写成 $\mathcal C(E,\mathcal S,M)$：$E$ 是视觉编码器，<font color=blue>$\mathcal S$ 是世界、动作及可选理解分支的集合</font>，$M$ 是注意力可见关系。组合规则 $\mathcal C$ 本身没有可训练参数；参数属于各个骨干和分支。这种拆分允许<u>在尽量复用其余组件的前提下</u>改变一个设计因素。（论文 §3）

框架还把训练与部署的数据约定写进检查点，包括解析后的结构配置和动作归一化统计。服务端负责<u>多视角预处理、本体状态映射、动作反归一化和 episode 重置</u>。这些细节直接关系到复现：即使权重相同，槽位映射或归一化不一致，也可能让输出动作失去原来的物理含义。

## 二、受控实验的前提：哪些是 ID，哪些是 OOD？

Study 主要依赖 RoboTwin 2.0 的两个协议：

| 协议 | 下游训练数据 | 评测含义 |
| --- | --- | --- |
| RoboTwin 2.0-Full | 2,500 条 clean 与 25,000 条 randomized 示范 | <font color=red>Clean 和 Random 都属于训练覆盖的设置</font> |
| RoboTwin 2.0-Clean2Random | 只使用 clean 示范 | <font color=red>Clean 作为 ID，Random 作为 OOD</font> |

因此，看到表格中的 Random 不能直接判断它是“未见分布”。同一个标签在两个协议中承担不同角色。

另一个容易误读的词是 **from scratch**。论文多数消融中的“从零训练”，指<u>没有经过额外的具身预训练</u>，仍然继承视频生成模型的预训练先验。<font color=blue>只有为了隔离视觉编码器影响的那组比较，特意采用随机初始化的 Wan DiT 结构。</font>

这些研究按顺序选择后续实验的默认配置。它们能回答“在当前设置下改变这一项会怎样”，但没有穷举所有组件组合，不能把每组最优选项拼成已经被证明的全局最优解。（论文 §4）

## 三、上游知识：更大的视频骨干与更紧凑的表征

### 3.1 规模带来提升，但这不是纯参数量定律

在 RoboTwin 2.0-Full 的视频骨干比较中，作者报告的平均成功率如下：

| 视频骨干 | 平均成功率 |
| :-: | :--: |
| Wan2.1-VACE-1.3B | 90.14% |
| Cosmos-Predict2.5-2B | 91.64% |
| ==Wan2.2-TI2V-5B== | 92.39% |
| ==Wan2.1-I2V-14B== | 93.79% |

更大的骨干在这组实验里表现更好，但模型的架构、预训练数据和目标也不同，不能把结果完全归因于参数量。作者最终选择 <font color=red>*Wan2.2-TI2V-5B*</font>，是因为它与 14B 模型相差 1.40 个百分点，同时更适合后续规模化实验。

> [!NOTE]
>
> 这组实验沿用<u>各视频骨干原生配套的视觉编码器，并未统一编码器</u>。因此，成功率差异反映了不同预训练模型及其配套表征的综合影响，不能单独归因于骨干参数量。

OpenWAM-Infra 支持的骨干范围更广；这张受控比较只包含上述四个模型，不能把框架支持列表当成同一组实验结果。（论文 §4.1）

### 3.2 语义特征并非无效，直接建模高维特征才是关键变量

视觉表征实验比较了<u>像素重建型 VAE</u> 与<u>语义特征编码器</u>。两者的主要区别在于**训练目标，以及潜在表示需要保留哪些信息**：

- **像素重建型 VAE（变分自编码器）**：先将图像或视频压缩为潜在表示，再通过解码器重建画面。重建目标要求表示保留足以恢复颜色、纹理和空间布局等画面细节的信息。本文比较的 Wan2.2-VAE 和 FLUX.2-VAE 属于这一类。
- **语义特征编码器**：通过自监督学习等方式提取有助于识别物体、理解场景结构或运动的视觉特征，训练重点是特征的一致性或可预测性，而不要求逐像素重建原图。本文比较的 DINOv3 和 V-JEPA 2.1 属于这一类；<u>这里的“语义”指学到的视觉表示，并非输出文字标签</u>。

在 WAM 中，视频分支学习预测的是这些编码器输出的潜在表示。VAE 表示有配套的像素解码器，语义特征则未必能直接还原为画面。这个分类不意味着 VAE 不含语义信息，也不意味着语义特征一定更紧凑；后者在本实验中反而需要通过 S-VAE 压缩维度，才能获得接近 Wan VAE 的表现。（论文 §4.1.2；另见 [VAE 原论文](https://arxiv.org/abs/1312.6114)与 [DINOv3 原论文](https://arxiv.org/abs/2508.10104)）

为避免匹配到某个预训练视频骨干的优势，这组实验使用<font color=red>随机初始化的 Wan DiT</font>，并统一为 4 倍时间压缩：Wan VAE 使用原生压缩，其余表征对每四帧进行平均处理。

| 视觉表征 | 设置 | 平均成功率 |
| :-: | :-: | :--: |
| ==Wan2.2-VAE== | 原生紧凑 latent | 90.30% |
| FLUX.2-VAE | 统一时间压缩 | 84.26% |
| DINOv3 | 原始 768 维特征 | 76.42% |
| DINOv3 + S-VAE | 压缩至 48 维 | 90.18% |
| V-JEPA2.1 | 原始 1,024 维特征 | 80.91% |
| V-JEPA2.1 + S-VAE | 压缩至 48 维 | 88.46% |

:target: https://pic1.imgdb.cn/i/034aWsRSct7XcMJsnSGCX3.png
:alt: Wan VAE、FLUX VAE、DINOv3 和 V-JEPA 表征消融，语义特征经过 S-VAE 压缩后成功率提高
:width: 100%

**原论文图 7：视觉表征消融**。高维语义特征经过 S-VAE 压缩后明显改善，因此结果不能简化为“像素表征优于语义表征”。

<u>DINOv3 + S-VAE 压缩后的结果已接近 Wan VAE。</u>这更支持一个有条件的解释：**用于生成建模的表征，既要保留控制所需的信息，也要有合适的维度和建模难度。** 原始特征在识别任务中很强，不意味着直接将其作为去噪目标就同样合适。（论文 §4.1）

## 四、世界与动作如何交互？

### 4.1 分开参数，通过注意力交换信息

Infra 定义六类架构。由于 Cross-Attention 额外比较了是否切断梯度，论文表 1 实际有七行结果。

| 结构 | 核心区别 | 平均成功率 |
| :-: | :-: | :--: |
| Single-Stream Vanilla | 视频与动作共用一条 Transformer 流 | 85.50% |
| Single-Stream MoE | 共享 token 投影层和注意力计算 + 动作 token 使用独立 FFNN 专家 | 84.63% |
| ==Dual-Stream Joint Self-Attention== | 视频与动作分别保留参数，在桥接层联合计算注意力 | 92.36% |
| Dual-Stream Joint Cross-Attention | 动作通过交叉注意力读取视频特征 | 88.25% |
| Dual-Stream Joint Cross-Attention + detached video | 梯度回传时切断该读取路径对视频分支的梯度 | 91.85% |
| Dual-Stream IDM | 训练时使用真实视频条件，推理时先生成视频再预测动作 | 87.95% |
| <del>Tri-Stream Joint Self-Attention</del> | 在双分支之外增加理解分支 | 92.60% |

> [!NOTE]
>
> 1. Tri-Stream Joint Self-Attention 三分支使用<u>冻结 VLM 提供的特征</u>和<u>可训练理解分支</u>，其他分支能够读取其表示。它在本表中略高于双分支；作者继续使用双分支作为研究主线，是为了减少复杂度，并避免额外 VLM 知识干扰后续分析。
> 2. 在这里的 Single-Stream MoE 中，同一层的视频 token 和动作 token 共享 Q / K / V 投影层的参数。 两类 token 拼接后进入同一个自注意力模块。
> 3. 这里的 Dual-Stream Joint Self-Attention 不等于视频和动作共享整套权重。两个分支拥有自己的参数，在桥接层将 Q / K / V 投影到兼容空间，再通过联合注意力交换信息。（论文 §3、§4.2）

### 4.2 “隔离”也能看当前观测

论文将 token 分成当前观测 $V_{\mathrm{obs}}$、未来视频 $V_{\mathrm{future}}$ 和动作 $A$。注意力图中，<font color=red>行是发出 query 的 token</font>，<font color=red>列是可读取的 key/value</font>。

| Isolated | 否 | 否 | 87.41% |
| Video-Sees-Action | 否 | 是 | 87.63% |
| ==Action-Sees-Video== | 是 | 否 | 92.39% |
| ==Mutual== | 是 | 是 | 92.15% |

## 五、联合去噪是否应该让视频先走一步？

### 5.1 两个噪声时刻，两个速度预测目标

OpenWAM 将视频 latent $z$ 与动作块 $a$ 都作为 flow matching 的生成目标。令 $\epsilon_v$、$\epsilon_a$ 为噪声，$t=0$ 对应噪声端，$t=1$ 对应数据端：

$$
\begin{aligned}
z_{t_v}&=t_v z+(1-t_v)\epsilon_v,\\
a_{t_a}&=t_a a+(1-t_a)\epsilon_a.
\end{aligned}
$$

网络分别预测视频和动作的速度，目标为 $z-\epsilon_v$ 与 $a-\epsilon_a$。省略语言、本体状态等条件后，目标可写为：

$$
\begin{aligned}
\mathcal L_v
&=\mathbb E\!\left[w(t_v)
\left\|\hat v_z-(z-\epsilon_v)\right\|_2^2\right],\\
\mathcal L_a
&=\mathbb E\!\left[w(t_a)
\left\|m\odot\left(\hat v_a-(a-\epsilon_a)\right)\right\|_2^2\right],\\
\mathcal L
&=\lambda_v\mathcal L_v+\lambda_a\mathcal L_a.
\end{aligned}
$$

$m$ 是有效动作维度的掩码。当前观测对应的干净首帧不参与视频预测损失，并在去噪过程中保持固定。

训练时 $t_v$ 和 $t_a$ 独立采样，因此模型会遇到视频清晰、动作较噪，或者相反的组合。推理时可以在这个二维噪声平面上选不同路径：同步推进，或让其中一个模态先接近数据端。（论文 §3、§5.1）

### 5.2 实验不支持固定的“先视频后动作”顺序

这里的**去噪调度**，规定每一步采样时视频与动作分别处于什么噪声水平。令 $s=i/N\in[0,1]$ 表示 $N$ 步采样中的全局进度，沿用上文 $t=0$ 为纯噪声、$t=1$ 为干净数据的约定。<font color=red>**同步调度（Sync）**：取 $t_v=t_a=s$，两条分支同步推进</font>；<font color=red>某个模态 “领先” ，指它在同一步采样中更接近干净数据端。</font>这里的时间是去噪进度，与视频帧的时间或机器人实际执行动作的时间不同。

**Variance-Shift 调度（方差偏移）**：通过非线性时间映射，让领先分支在中间步骤的去噪进度大于另一条分支。论文使用的映射为：

$$
f_{\alpha}(s)=\frac{\alpha s}{1+(\alpha-1)s},\qquad \alpha>1.
$$

以视频领先为例，取 $t_v=f_{\alpha}(s)$、$t_a=s$。例如 $\alpha=4$、$s=0.5$ 时，视频的去噪时间为 $t_v=0.8$，动作则为 $t_a=0.5$。两条分支都从一开始推进，但视频在中途更接近干净数据；$\alpha$ 越大，领先程度越明显。两者仍在 $s=1$ 时到达终点，$\alpha=1$ 则退化为同步调度。

**Linear-Offset 调度（线性偏移）**：让落后分支先保持在纯噪声状态，待全局进度超过偏移量 $o$ 后，再在线性压缩的剩余区间内完成去噪：

$$
h_o(s)=\max\!\left\{\frac{s-o}{1-o},\,0\right\},\qquad 0\le o<1.
$$

同样以视频领先为例，取 $t_v=s$、$t_a=h_o(s)$。当 $o=0.4$ 时，动作在前 40% 的全局进度内保持纯噪声；到 $s=0.7$ 时，视频的去噪时间为 $t_v=0.7$，动作则为 $t_a=0.5$，最后两者都在 $s=1$ 时完成。$o$ 越大，动作开始去噪越晚；$o=0$ 则恢复同步调度。

将上述视频与动作的角色互换，就得到动作领先的方案。因此，两种调度分别通过**改变推进曲线**和**延迟去噪起点**形成进度差。这组消融<u>固定双向可见的注意力掩码（Mutual），比较的是推理时的噪声进度安排</u>。（[论文 §3.3，式（3）及 §4.2.3](https://arxiv.org/pdf/2609.07398v1)）

图 9 中，同步方案达到 93.0%，是所测设置中最高的结果。

:alt: 同步去噪与视频领先、动作领先的两类时序比较，同步方案达到百分之九十三

**原论文图 9：推理去噪时序消融**。在不同调度族中，哪一个模态领先更好并不一致；同步联合去噪最稳妥。

<font color=red>在 Variance-Shift 调度里，视频领先相对更好；在 Linear-Offset 调度里，则是动作领先相对更好。</font>因而不能仅凭「动作需要未来信息」就推断「视频应该先生成完」。两种模态逐步交换信息，也是一条有效路径。

这个实验与 [Fast-WAM](FastWAM-paper.md) 讨论的“能否移除推理时未来想象”不是同一个问题。<font color=red>OpenWAM-α 仍然联合去噪未来视频 latent 和动作；部署时不把 latent 解码成 RGB 视频，只是省去了 VAE 解码，不能理解成完全跳过未来 latent 的预测。</font>

## 六、600 小时预训练：主要收益来自 OOD

### 6.1 混合数据提高了分布外成功率

作者固定骨干 / 预训练预算 / 推理方式和下游微调流程，比较 600 小时具身预训练数据：机器人组使用 RoboCOIN；混合组使用 350 小时 EgoDex 与 250 小时 RoboCOIN。评测采用 Clean2Random 协议。

| 预训练设置 | 数据组成 | ID 成功率 | OOD 成功率 |
| :-: | :-: | :--: | :--: |
| 无具身预训练 | 继承视频先验，直接下游微调 | 87.00% | 14.50% |
| Robot-only | 600 小时机器人数据 | 88.50% | 23.80% |
| Ego → Robot | 先 ego 数据，再机器人数据 | 87.10% | 26.50% |
| ==Ego + Robot== | 两类数据联合预训练 | 87.68% | 26.62% |

**Ego → Robot** 表示同一个模型的两阶段顺序预训练：先用人类第一人称视角（egocentric）数据学习场景变化、物体运动和操作过程，再继承这一阶段的模型权重，用机器人交互数据继续预训练，使学到的视觉与动态知识进一步适配机器人动作。箭头表示训练顺序；**Ego + Robot** 则在同一预训练阶段混合使用两类数据。两种方案完成预训练后，都会进行下游任务微调，再评测成功率。（论文 §4.3）

这组结果提示，<u>训练分布内的高成功率可能掩盖预训练价值</u>。ID 已接近饱和时，额外数据更明显地改善了分布变化下的表现。

但还需保留两个边界。第一，实验没有 Ego-only 组，不能据此完全拆清 egocentric 数据的独立贡献（实际上 ego 数据很难直接 pretrain 并在 benchmark 中微调）。第二，顺序训练和联合训练的 OOD 只差 0.12 个百分点，<u>没有必要把联合训练描述成巨大优势；它同时也是更统一的数据管线选择</u>。（论文 §4.3）

## 七、OpenWAM-α：把研究结论落到一个具体模型

### 7.1 5B 视频分支与 1B 动作分支

最终模型从 <font color=red>*Wan2.2-TI2V-5B*</font> 初始化视频分支，并加入约 1B 参数的 Action DiT。Wan2.2 VAE 与 umT5 文本编码器冻结，视频分支、动作分支及本体状态编码器参与训练。

| 组件 | 具体设置 |
| --- | --- |
| Video DiT | 隐藏维度 3072，30 层 |
| Action DiT | 隐藏维度 1024，30 层 |
| 分支桥接 | 30 **对层全部交互**，统一注意力空间为 24 个头 × 128 维 |
| 视觉位置编码 | 视频 token 使用 3D RoPE |
| 动作位置编码 | 动作 token 使用 1D RoPE |
| 语言与状态 | 4096 维文本特征；80 维本体状态投影为额外 context token |
| 跨模态关系 | Mutual，但干净当前观测不读取未来视频或动作 |
| 推理采样 | 视频与动作同步，10 步 Euler 更新 |

```{figure} https://pic1.imgdb.cn/i/034aWt0Nl263myODskAk2Y.png
:target: https://pic1.imgdb.cn/i/034aWt0Nl263myODskAk2Y.png
:alt: OpenWAM alpha 的双分支模型、视频与动作训练、数据组成以及统一动作空间
:width: 100%
:align: center

**原论文图 12：OpenWAM-α 的完整配方**。视频生成先验、双分支交互、混合具身数据和统一动作接口共同构成最终模型。
```

多相机图像先拼接成一张画布。因果视频 VAE 单独编码首帧，之后每四帧形成一组，时间长度从 $T$ 变为 $T'=1+(T-1)/4$；latent 再按 $(1,2,2)$ 切块。这样，当前观测可以作为不含未来信息的干净条件。

训练时两个损失权重均为 1，时间权重 $w(t)$ <u>在中间噪声区域较大</u>。视频和动作时刻独立采样；推理则使用论文给定的统一时间网格，始终钳制当前观测 latent，不对其进行生成。（论文 §5.1）

### 7.2 统一 80 维动作空间，靠掩码处理异构数据

不同机器人不能简单共用原始动作向量。OpenWAM-α 采用固定槽位表示：

$$
80=2\times(3+6+1+24)+12.
$$

每侧包含位置 3 维、旋转 6 维、夹爪 1 维和手部 24 维，另预留 12 维。这个统一空间并不意味着每台机器人都有 80 个有效自由度。

输入动作先在原生空间归一化，再通过 Scatter 放入固定槽位；输出时先 Gather 出当前机器人的有效槽位，再反归一化回原生控制空间。无效维度通过掩码排除。

<font color=red>Ego 视频没有机器人动作标签，其动作与本体状态槽位全部屏蔽，只提供视频监督</font>。因此，后面提到的 5.185 亿帧不能理解成 **5.185 亿帧带机器人动作标注的数据**。

## 八、大规模数据：比例只是起点，质量筛选同样重要

### 8.1 从原始池到最终保留集

最终预训练数据池原始规模约为 13.339 亿帧、14,348 小时；清理和配额选择后，保留约 5.185 亿帧、6,369 小时。

| 来源 | 保留帧数（百万） | 时长（小时） | 帧数占比 |
| :-: | :--: | :--: | :--: |
| 作者构建的 ego 视频数据 | 155.7 | 1,442 | 30.1% |
| AgiBot World Beta | 96.9 | 1,794 | 18.6% |
| RoboCOIN | 74.1 | 686 | 14.3% |
| DROID | 36.3 | 1,007 | 7.0% |
| InternData-A1 仿真数据 | 155.5 | 1,440 | 30.0% |
| **合计** | **518.5** | **6,369** | **100%** |

总体目标为约「30% ego 数据 + 40% 真实机器人 + 30% 仿真数据」。**这里的比例按保留帧数／样本预算理解，不是按小时混合**；不同来源的帧率不同，小时数占比不会相同。

作者通过固定随机种子和完整 episode 选择落实来源配额，并在来源内部平衡子集预算，再按照保留样本比例组织训练。这样可以避免仅用“每个数据集取多少小时”来描述实际看到的训练分布。（论文 §5.2）

### 8.2 清理规则尽量保留真实的时序关系

论文的数据清理不只是删除模糊画面，还检查视觉与控制信号是否一致：

- **视觉质量**：剔除解码失败、冻结或重复帧、异常曝光、闪烁、严重模糊和突变；ego 数据还<u>检查手部可见性与语言有效性</u>。
- **控制与同步**：检查异常轨迹、控制信号跟踪问题，以及视频和动作是否对齐。
- <u>**静止段处理**：裁掉 episode 开头和结尾的空闲片段，保留过程中的停顿，避免将非相邻时刻拼接成虚假的连续运动。</u>
- **多相机交叉检查**：区分真实静止、状态噪声和视频采集冻结；质量损失过大的 episode 整段移除。

对预测未来的模型来说，第三点尤其重要。中途停顿可能是任务的一部分；如果为了提高“运动密度”而随意删帧，会改变动作与视觉的时间对应关系。

### 8.3 训练规模与下游适配

论文附录给出的预训练配置为：**128 张 H200，约 7 天；全局 batch size 3072，训练 155,862 步，约一个 epoch**。优化器为 AdamW，学习率 $10^{-4}$，5% warmup 后进行余弦衰减，使用 BF16 和 ZeRO-2。视频训练片段为 33 帧，时间采样间隔为 4，图像分辨率为 384 × 320。（论文附录 B）

这个成本说明，完整配方是大规模预训练实验。对资源较少的复现工作，更现实的切入点是使用发布的预训练检查点，在固定下游设置里验证结构或数据因素。

**最终模型的各项 benchmark 结果来自同一个预训练检查点分别进行下游微调。** 它们不是一个未经适配的策略直接跨八个基准测试。<font color=red>LIBERO-Plus 复用 LIBERO 微调后的模型，不再对其扰动数据进行额外微调</font>。

## 十一、部署结果要区分两种“同步”

论文中有两个不同层面的同步：

1. **模型内部的同步去噪**：视频和动作按同一时间进度更新。
2. **机器人执行的同步服务**：动作缓冲区耗尽后等待下一次推理结果。

Infra 支持异步预取，但论文报告的 benchmark 使用同步执行。因此，不能把服务框架支持异步的能力写成所有实验已经验证了异步闭环收益。

作者报告 RTX 5090 上约 170 ms 生成一个动作块，使用 10 步去噪，并**结合编译、CUDA Graphs、速度缓存、提示词缓存以及省略 VAE 解码等优化**。这是特定配置下的块推理延迟，不等同于机器人控制频率；实际执行还受动作块长度、控制周期和调度方式影响。（论文部署部分与附录）

## 十二、我从这篇论文中带走的结论

**第一，表征的可生成性与信息含量需要一起考虑。** DINOv3 （以及 V_JEPA 2.1 这个编码器）经过 S-VAE 压缩前后相差很大，说明使用更强视觉编码器并不足以定义一个更好的 WAM ；latent 的维度、冗余和预测难度也值得单独实验。

**第二，结构消融要跟着训练规模重做。** 是否让视频读取动作，在具身预训练前后出现不同趋势。小数据设置下的选择可以作为起点，但不能直接替代大规模配方的验证。

**第三，评估预训练不能只看 ID。** 600 小时实验的主要收益在 OOD；最终模型在 LIBERO-Plus 又显示出明显的相机和噪声短板。两者共同提示，平均成功率需要配合扰动类别与训练覆盖范围阅读。

**第四，数据与接口也是配方的一部分。** 完整 episode 的选择、中途停顿的保留、视觉动作同步、动作槽位与归一化，都会影响模型究竟学到什么以及部署时能否正确执行。

论文自身也指出，当前研究主要覆盖具身预训练，对后训练、更多融合结构和适配方式仍有探索空间；数据未覆盖 UMI / DexUMI 等来源，紧凑又鲁棒的视觉 latent 也尚待改进。OpenWAM 提供的是一套可扩展的研究基础和经过实验支持的起点，而不是已经终结的 WAM 设计答案。（论文附录 A）

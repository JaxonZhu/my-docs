# OpenRUA 论文解读：通过 ROS 2 编程控制机器人

论文原题：OpenRUA: Robot-Use Agents Are Zero-Shot Visuomotor Policies

- 作者：Zhaoyang Chu、Earl T. Barr、Claire Le Goues、Peter O’Hearn、Mark Harman、Federica Sarro、He Ye
- 团队：伦敦大学学院、卡内基梅隆大学
- 论文：[arXiv:2610.02459v1](https://arxiv.org/abs/2610.02459v1)，2026 年 10 月 1 日
- 状态：预印本；截至 2026 年 10 月 10 日，未查到官方会议或期刊接收公告
- 代码与演示：[terminalworld/OpenRUA](https://github.com/terminalworld/OpenRUA)

OpenRUA 研究的是：**现成的编程 Agent 能否借助机器人已有的 ROS 2 接口，在任务执行中自行编写感知和控制程序？** 作者把机器人当作一个可以交互的软件项目：Agent 阅读机器文档、获取观测、计算目标、运行程序，再根据结果调整动作。

采用 Claude Code 与 Claude Opus 5 时，论文报告 CaP-Bench 成功率 **99.0%**、LIBERO-PRO 成功率 **87.0%**。这些结果全部来自仿真，且 Agent 思考时仿真暂停。因此，它首先展示了编程式机器人策略的任务求解能力，实时真机执行仍有待验证。

## 一、零抽象层具体省掉了什么？

作者将设计称为 **zero-abstraction harness**：不额外定义一套供 Agent 调用的任务专用 API，也不规定固定的观察、规划、执行流程。Agent 使用已有的 `ros2` 命令行工具和 `rclpy` Python 库访问机器人的 topics、services 与 actions。

ROS 2、逆运动学、轨迹执行和底层控制器仍然存在，初始工作区也提供文档与可运行的工具。“零抽象层”描述的是减少额外的 Agent 专用封装，并不表示机器人无需软件集成或控制工程。（论文 §3、附录 B）

| 初始材料 | 提供的信息或能力 |
| --- | --- |
| `README.md` 与机器文档 | 工作区入口、接口使用方法和通用操作建议 |
| `machine.yaml` | 传感器、ROS 端口、关节限制、坐标系与夹爪属性 |
| 六个 Python starter tools | 相机快照、像素反投影、关节轨迹、夹爪控制、IK 移动、基座导航 |
| 可写工作区 | 保存本轮图像、数组、程序、测量结果和日志 |

附录 H 列出的工具已经包含像素到世界坐标的转换，以及基于里程计反馈的移动底座控制。Agent 可以直接使用、修改或替换这些实现；运行时生成的任务程序并不是在完全没有感知与控制示例的条件下产生的。

这里的 **zero-shot** 有明确的实验含义：每个 episode 都从新的 Agent 会话和工作区开始，不提供机器人示范、任务预演或前一轮积累的经验。文件与任务经验不会传入下一轮，不能将这种任务内记忆理解为跨任务学习。（附录 B.2、C.2）

## 二、感知变成文件读取与几何计算

Agent 按需订阅 ROS 2 传感器消息，把 RGB 图像、深度数组、关节状态或力反馈写入工作区。模型可以查看图像，程序则负责计算坐标、物体尺寸、夹爪间隙等数值。

例如在 Nut 任务中，Agent 从顶视图识别螺母和柱子，再用深度高度分割和相机标定计算世界坐标。它还裁剪、放大螺母区域并叠加像素网格，以判断抓取方向；抓取后结合腕部图像和夹爪间隙检查是否拿住。（论文 §4.3）

```{figure} https://pic1.imgdb.cn/i/034dFJdpeH11POWyI1kb8G.png
:target: https://pic1.imgdb.cn/i/034dFJdpeH11POWyI1kb8G.png
:alt: Agent 在螺母任务中查看顶视 RGB、按高度分割深度、放大局部并加网格，最后用腕部相机检查抓取
:width: 100%
:align: center

**原论文图 4：视觉判断与程序测量互相补充**。图像帮助选择目标和检查结果，深度与标定提供动作所需的度量坐标。
```

作者对 CaP-Bench 与 LIBERO-PRO 的 **1,500 个 episodes** 分析发现：72.67% 读取了自编图像处理程序输出的图像，96.80% 执行了自编的度量计算程序。统计包含成功与失败案例，表示这些行为出现得多频繁，并非每次测量都正确。（原论文表 2）

一个容易忽略的接口细节是：深度 PNG 只是可视化，实际几何运算应使用保留数值与单位的 `.npy` 数组；分别保存 RGB 和深度，也不自动保证二者时间同步。标定、坐标变换与观测对齐仍然是可靠测量的基础。（附录 B.3）

## 三、Agent 决策与程序控制形成两层反馈

OpenRUA 中存在两种不同的闭环。

**Agent 层的闭环**发生在工具调用之间：观察结果、判断操作是否成功、修改目标或代码，再次执行。**程序层的闭环**发生在已经运行的控制程序内部：反复读取传感器，依据阈值调整动作或停止，不需要每一步都重新调用大模型。

在一个抽屉任务中，Agent 先编写 ROS 2 客户端，把逆运动学、轨迹、夹爪和速度接口整理成可复用函数；随后编写拉动程序，每次短距离运动后检查夹爪间隙和位移。若夹爪间隙小于 8 mm，或位移不足 1 mm，程序就停止并返回状态。（论文 §4.4、图 6）

在同样的 1,500 个 episodes 中，95.87% 出现自编运动控制客户端，50.13% 执行了带传感器反馈逻辑的自编程序。后一个数字不能解释成“剩余任务都是开环”：Agent 在程序调用之间仍可能通过重新观察进行纠错。（原论文表 3）

```{figure} https://pic1.imgdb.cn/i/034dFJigxEnFDEq5pCWbeu.png

:alt: Agent 首次抓取番茄酱瓶失败后，重建倒下瓶子的几何形状，调整抓取姿态并放入篮子
:width: 100%
:align: center

**原论文图 7：Agent 层面的失败恢复**。首次抓取将瓶子碰倒后，Agent 根据夹爪间隙与相机图像发现失败，重新测量并调整抓取方案；这是一个执行案例。
```

这也解释了它与已有两篇笔记的关系：[Agent as Policy](Agent-as-Policy-paper.md) 同样让 Agent 在执行期间观察、编程和纠错，采用专门的 Robot Bridge，并给出了真机实验；[Harness VLA](Harness-VLA-paper.md) 则把冻结 VLA 作为局部操作工具，由 Agent 编排调用。OpenRUA 选择直接使用 ROS 2 原生接口，在运行时构造控制程序，其论文评估范围是仿真。

## 四、主结果需要连同评估协议阅读

### 4.1 三组仿真任务

主实验使用 Claude Code、Claude Opus 5 与 high reasoning effort，共 **2,000 个 episodes**。（论文 §4.1、附录 C）

| 基准 | 覆盖范围 | Episodes | OpenRUA 成功率 |
| --- | --- | --- | --- |
| CaP-Bench | 七项单臂、双臂任务，每项 100 次 | 700 | **99.0%** |
| LIBERO-PRO | 四个 suite × 两种扰动，每格 100 次 | 800 | **87.0%** |
| RoboCasa365 | 50 项厨房任务，每项 10 次 | 500 | **39.4%** |

CaP-Bench 中，Lift、Stack、Wipe、Nut、Restack 五项均为 100%，双臂 Lift 为 99%，Handover 为 94%。对照表里的 Human Expert 82.6% 是基准已有的专家编写程序成绩，不能理解为此次与人类现场操作做了对比。

LIBERO-PRO 的两种扰动分别是位置变化 P 和任务指令变化 T。四个 suite 的细分结果如下：

| Suite | 位置扰动 P | 任务扰动 T |
| --- | --- | --- |
| Object | 98% | 97% |
| Spatial | 98% | 100% |
| Goal | 79% | 79% |
| LIBERO-10 | 80% | 65% |

前三行六个单元的平均为 **91.8%**，包含 LIBERO-10 后的八单元平均才是 **87.0%**。论文引用的 Harness VLA 最佳八单元结果为 82.4%，差值为 **4.6 个百分点**；六单元成绩不能直接拿来与八单元均值比较。（原论文表 1）

### 4.2 四项影响成绩解释的条件

首先，每轮最多 **500 次模型响应或 240 分钟有效墙钟时间**，先到者结束，没有额外的仿真步数上限。墙钟时间包含推理与工具执行，但暂停等待模型服务恢复的时间不计入预算。

其次，仿真只在控制命令推动环境时前进，Agent 思考和读取观测时暂停。控制程序可以持续发命令推进仿真，但大模型推理延迟不会直接让物体或机器人继续运动。

第三，评估器独立检查成功条件，Agent 看不到目标物体的特权位姿、成功判定函数或评分结果。**终止前任何一步满足条件即记为成功，之后状态改变也保留这次成功**；评分既不是 Agent 自称完成，也不只看最后一帧。

最后，基线成绩来自已有论文，作者没有统一重跑。模型、推理预算、传感接口、先前经验、试次数和终止规则均可能不同。因此，这些表格比较的是已发表的完整系统配置，不能单独证明“移除接口封装”造成了全部提升。各主设置只运行一次所述样本集，小幅差异未作显著性判断。（附录 C.2–C.4）

### 4.3 未见组合任务有收益，整体表现仍有差距

RoboCasa365 将 50 项任务分为 18 项原子任务、16 项已见组合和 16 项未见组合。“已见／未见”指任务模板是否出现在该基准的预训练示范中，不是 OpenRUA 是否尝试过这些任务。

| 系统配置 | 原子任务 | 已见组合 | 未见组合 | 总体 |
| --- | --- | --- | --- | --- |
| RLDX-1 | 60.0% | 21.3% | 5.0% | 30.0% |
| Harness VLA，GPT-5.5 | 92.0% | 61.0% | 13.8% | 57.1% |
| Harness VLA，Opus 4.7 | 79.4% | 47.5% | 15.0% | 48.6% |
| OpenRUA，Opus 5 | 61.1% | 26.3% | **28.1%** | 39.4% |

数据来自原论文表 4；总体按三组的任务数加权。OpenRUA 的已见与未见组合成绩相近，在未见组合上超过表中这些系统，但总体低于两种 Harness VLA 配置。它支持运行时编程在任务组合变化下的潜力，也保留了已有局部技能在其他任务上的优势。

```{figure} https://pic1.imgdb.cn/i/034dFJkRM6zJN9dYKatP5h.png
**原论文图 8：按首次成功时刻回看计算预算与成功率**。这些曲线由已有运行记录统计得到，并非对每个预算点重新启动一组受限实验。
```

在 LIBERO-PRO 的 LIBERO-10 子集上，每种配置评估 200 次。Opus 5 在 100、150、200 次响应内已经成功的比例分别为 50%、66%、70%，最终为 72.5%。同一 Codex 与 GPT-6 Astra 配置从 medium 提高到 high 推理强度，成功率从 62.5% 增至 69.0%。（论文 §4.6、附录 F）

计算量并不等于任务能力：Sonnet 5 的最终成功率为 24.0%，每轮响应次数中位数为 301；Opus 5 为 72.5% 和 103 次；Fable 5.1 为 75.0% 和 73 次。更长的交互也可能意味着模型迟迟未能解决问题。

论文按 2026 年 9 月 20 日的 API 标价折算，Opus 5 平均每轮等价成本为 13.7 美元，按“总费用除以成功次数”计算，每次成功为 18.9 美元。实际运行采用订阅，因此这些数字不是实付账单，也不是当前报价；成本与成功率需要共同评估。（原论文表 11）

## 六、我的理解与适用边界

我认为 OpenRUA 最值得关注的是：通用编程能力开始参与任务中的几何测量、控制逻辑构造和失败恢复。工作区让这些中间结果可以保存和复用，ROS 2 则提供已有的机器能力接口。它把一部分预先编写任务逻辑的工作，转移到了执行现场。

但“写出了反馈程序”与“可靠地完成机器人控制”仍有距离。作者分析的 413 个失败 episodes 中，238 个被归入任务条件未说明、判定与指令冲突或未记录的机器行为，100 个归入 Agent 的感知、控制或等待错误。这个分类由执行记录分析得到，包含歧义案例，不能据此断言消除基准问题就能补回相应成功率。（论文 §4.7、附录 G）

真正从仿真走向现实，还需要跨过三个与本文结果直接相关的条件：

- **时间持续流逝**：真实环境不会等待大模型思考，程序内部的反馈也无法消除两次 Agent 决策之间的延迟。
- **传感误差**：仿真中的深度与标定不足以代表真实噪声、缺失深度和异步观测，几何程序同样可能受到影响。
- **独立控制约束**：失败案例包括可能撞桌的轨迹；Agent 自己写的力阈值与停止条件不能代替独立的运动限制、碰撞检查和急停机制。

这项工作的证据支持“现成编程 Agent 可以在明确接口和充足预算下完成广泛的仿真操作”，更进一步的实时性与真机可靠性需要单独验证。

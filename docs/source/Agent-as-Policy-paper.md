# Agent as Policy 论文解读：让通用 Agent 在机器人执行中观察、编程与纠错

论文原题：Agent as Policy for Robotic Manipulation

- 作者：Mengzhao Jia、Yang Lin、Xixin Zhang、Zhihan Zhang、Xiaobai Liu、Meng Jiang
- 团队：University of Notre Dame、University of California San Diego、San Diego State University
- 论文：[arXiv:2609.12541v3](https://arxiv.org/abs/2609.12541v3)，2026 年 9 月 28 日更新
- 项目与演示：[Agent as Policy](https://agent-as-policy-2026.github.io/)
- 代码：[agent-as-policy-2026/agent-as-policy](https://github.com/agent-as-policy-2026/agent-as-policy)
- 数据与执行记录：[Hugging Face](https://huggingface.co/datasets/Agent-as-Policy/agent-as-policy)

Agent as Policy（AGP）研究的是：**一个通用 Agent 能否在模型权重不变的情况下，通过看图、写程序、调用机器人接口和检查实际结果，完成多种真实操作任务？** 作者把 Agent 留在整个执行过程中，让它决定何时观察、如何估计物体位置、怎样生成动作，以及失败后如何修改方案。

这里的 policy 指运行时的决策者。Agent 提交末端位姿、关节角和夹爪目标；逆运动学、轨迹生成和电机控制由独立控制器负责。论文没有让语言模型直接输出电机力矩，也没有把相机帧率当成 Agent 的决策频率。

主实验覆盖装配、搭积木、翻骰子、定向投掷和双臂折毛巾五组任务、八种配置，其中七种配置的成功率不低于 80%。与此同时，许多成功任务仍需要几十分钟。理解这项工作的价值，需要同时看它能临场解决哪些问题，以及为此付出了多少观察、推理和执行成本。

## 一、Agent 在什么层级上充当策略？

### 1.1 从预先生成程序到执行时持续决策

机器人可以先由语言模型生成一段程序，再把它交给执行器运行；也可以由高层 Agent 调用已经训练好的局部技能。AGP 关注的变化是：**执行现场出现的新信息，可以直接改变后续程序和动作。**

例如，插入失败后，Agent 可以重新拍照、放大局部区域、写一个几何计算程序，估计手中零件相对夹爪的偏移，再修改目标位姿。它也可以发现原来的抓取姿态无法使管子竖直，转而倾斜夹爪重新抓取，而不是持续重放同一段失败动作。（论文 §3）

| 系统部分 | 负责什么 | 输出或结果 |
| --- | --- | --- |
| 准备 Agent | 整理任务说明、参考材料、约束和成功标准 | 可复用的任务定义 |
| 执行 Agent | 选择观察、编写和运行程序、提交动作、检查结果 | 下一次工具调用 |
| Robot Bridge | 传递观测与动作请求，反馈执行状态和错误 | 图像、状态、动作结果 |
| 独立控制器 | 逆运动学、轨迹生成、运动跟踪 | 实际机械臂与夹爪运动 |

“无需任务专门训练”指没有为当前任务或环境更新模型参数。系统仍依赖预训练多模态模型、任务参考材料、相机标定、接口文档和已搭好的控制系统。

### 1.2 策略的输入不只有当前图像

论文用下面的形式描述第 $k$ 次工具决策：

$$
u_k \sim \pi_\theta(\cdot\mid g,\mathcal I,H_k,W_k).
$$

其中，$g$ 是任务定义，$\mathcal I$ 是机器人接口，$H_k$ 是交互历史，$W_k$ 是当前本地工作区，$\theta$ 在执行期间保持不变。这里的 $u_k$ 可以是拍照、读状态、处理图像、运行脚本或提交动作的工具调用，不能直接等同于一个低层动作向量。

工作区使策略能够积累可操作的信息：之前保存的图像、测量结果、尚待修正的程序、已经验证过的操作步骤，都可能影响下一次决策。一次工具调用也可以包含多个操作，但交互预算仍按其中实际发生的观察与动作请求计数。（论文式 1、附录 B.3）

### 1.3 准备阶段与执行阶段

遇到一种新任务时，准备 Agent 读取用户指令、示范视频或目标图像、机器人接口文档及已有任务提示，生成任务定义。定义包括目标、约束、完成标准、工具使用规则、预算与日志要求。后续同类任务实例复用这个定义，并补充当前实例信息。

执行 Agent 随后根据真实观测选择行动，决定何时获取新信息、运行程序或提交下一步动作。（论文 §3.1）

## 二、把图像变成机器人可以执行的目标

### 2.1 硬件与七个接口

主要实验使用 I2RT YAM 六轴机械臂与平行夹爪，折毛巾任务使用两条机械臂，并通过标定变换共享坐标系。手腕相机为 Intel RealSense D405，提供 640×360 的对齐 RGB 与深度；固定顶视 Logitech BRIO 提供 1920×1080 的校正 RGB 图像。

两类相机流速均为 30 fps，但 Agent 按需请求观测。相机持续采集与模型多久决策一次，是两件不同的事。（论文 §4.1、附录 A）

### 2.2 几何定位需要标定，也需要处理误差

手腕图像可以借助深度、相机标定和机器人位姿，将像素映射到机械臂基坐标系。顶视 RGB 没有直接的深度测量，需要将像素对应的空间射线与估计高度平面求交，或结合其他视角进行定位。

附录给出了运行时编程的具体例子：

- **抓取偏移补偿**：Agent 创建 `fit_head.py`，从手腕深度点拟合平面、用 SVD 估计法向，再结合顶视射线和零件长度估计销尖相对夹爪的偏移。计算结果被用于修改真实动作目标，收到到达误差后继续调整。
- **多视角定位**：`triangulate.py` 将两个视图中选定的像素变成标定射线，求两条射线的最近点，以中点估计三维位置，以两点间距检查一致性。像素对应由 Agent 提供，因此一致性好也不等于三维坐标没有误差。
- **双臂调用组合**：`step.py` 读取双臂状态、并发派发各自的操作，再拍照检查结果，同时保存完整日志。

作者分析的 65 次机器人执行中，18 个会话保留了 37 个运行时 Python 工作文件：29 个主要用于感知与几何、7 个用于组合机器人调用、1 个用于视觉标注。另有 48 个会话包含共 135 次带内联 Python 的 shell 事件；它们与文件统计有重叠，不能相加当成独立程序数。这些实例展示了程序如何进入动作决策，但论文没有通过消融单独测量每类程序的贡献。（附录 E）

### 2.3 投掷依赖专门的定时执行接口

普通动作有较保守的限制：关节速度 20°/s、加速度 40°/s²，末端平移 0.03 m/s、姿态变化 10°/s。运行时还限制目标径向范围为 0.12–0.65 m，单次笛卡尔移动不超过 0.25 m。

投掷另用专门的运行时：Agent 提交带时间节点的关节偏移和夹爪目标，执行器按 **50 Hz** 插值执行，将挥臂与释放时机对齐；其中关节 4 的速度、加速度限制提高至 180°/s、360°/s²。

因此，投掷展示了 Agent 如何构造和调整一个定时动作程序，**50 Hz 是执行器的插值频率**。推理延迟与抓持物体实际脱离夹爪的延迟，仍是不同层面的问题。（附录 A.1、F.6）

## 三、五组任务、八种配置，成功如何判断？

| 任务组 | 目标输入 | 具体要求 |
| --- | --- | --- |
| 四对零件装配 | 人类示范视频 | 将八个零件按示范顺序装成四对，后续操作不能破坏已完成的组合 |
| 积木搭建 | 目标图像 | 用六个方块搭出金字塔、两座塔或六层塔，共三种配置 |
| 翻骰子 | 任务指令及参考信息 | 将六个骰子都调整为指定数字朝上 |
| 定向投掷 | 语言指令 | 通过挥臂与释放将物体投向目标区域，满足指定的飞行与落点要求 |
| 双臂折毛巾 | 人类示范视频 | 先折长边，再依次或同时向内折两侧短边，共两种配置 |

每项任务预先规定场景条件、预算和判定标准，允许 Agent 在预算内自主恢复。积木初始位置在试次间变化；折毛巾从近似示范初始布局开始。成功判定依据最终物理状态和视频，并要求释放夹爪、撤开机械臂后仍满足装配、支撑、朝向或折叠关系。（论文 §4.1、附录 B）

这条判定规则很关键。一个六层塔可以在释放时站立，却在机械臂撤开时倒塌；一个零件可以挂在接收件上，却没有稳定插入；毛巾看起来变小，也可能仍留有未折的角。Agent 自报“完成”只是执行终止信号，不能替代物理评估。

## 四、主结果与成功试次的执行成本

主实验使用 GPT-6 Astra。下表转录 PDF 表 1 的均值，保留成功数与总试次数；时间单位为分钟，token 单位为百万，费用为美元。

| 任务配置 | 成功数 / 总数 | 时间 | Tokens | 推理费用 |
| --- | ---: | ---: | ---: | ---: |
| 四对装配 | 8/10 | 37.2 | 13.02 | 16.62 |
| 金字塔 | 10/10 | 21.6 | 9.24 | 11.69 |
| 两座塔 | 10/10 | 20.6 | 7.94 | 9.92 |
| 六层塔 | 9/10 | 28.2 | 11.57 | 14.93 |
| 翻六个骰子 | 10/10 | 37.9 | 17.08 | 21.07 |
| 定向投掷 | 9/10 | 17.71 | 5.71 | 8.16 |
| 依次折毛巾 | 5/5 | 50.8 | 18.12 | 24.14 |
| 同时折毛巾 | 3/5 | 21.4 | 5.06 | 7.46 |

**统计口径**：除投掷外，时间、tokens 与费用仅对成功试次取平均；投掷汇总全部 10 次会话，并包含最终报告时间。普通任务的完成时间从任务交付计到最终物理验证，包含推理、程序构造、观察、动作与恢复。推理费用包含缓存输入等 API 计费项目，不包含完整硬件与运维成本。（论文表 1、附录 B.3、D.1）

Tokens 是所有模型请求的输入与输出累计，包括重试和重复上下文；不能将数百万 token 理解为 Agent 新写了等量文字。论文将 reasoning tokens 计入输出一次，避免重复统计。

这些结果说明系统能够在所测场景中组合复杂操作，但样本量仍只有每配置 5 或 10 次。10/10 或 5/5 不意味着对任意摆放、物体或环境都具有 100% 成功率。依次折毛巾更慢但成功率更高，同时折叠则为 3/5；两者策略、结果和计时样本不同，不能把时间差全部归因于双臂并行。

图中的 visual loop 包括拍照、几何查询、图像处理，以及看图之后的模型响应；这部分响应也可能包含规划和代码生成。因而不能把它全算作摄像头耗时，也不能把图中各块解释成严格分离的神经网络计算成本。

作者观察到，装配与折毛巾的大量时间用于观察场景并决定下一步。单独一个四对装配案例中，推理与规划占总会话约 68.2%，但这是该案例的分解，不能外推成所有任务都具有同样占比。（论文图 3、附录 D.1）

**我的理解**：AGP 的效率问题包含减少重复判断、复用几何程序、组织工具调用和等待机器人完成等多个部分。只提升机械臂运动速度，不一定能消除占时较多的观察与推理环节。

### 5.2 与 GaP、ASPIRE 的成功率比较

作者将 Graph-as-Policy（GaP）和 ASPIRE 适配到所用实验环境，三种方法均使用 GPT-6 Astra high。GaP 构造策略图并在仿真中改进，ASPIRE 通过调试、搜索和技能复用形成程序；AGP 在实际执行过程中继续观察并调整。

| 方法 | 两对装配 | 四对装配 | 金字塔 |
| --- | ---: | ---: | ---: |
| GaP | 0/5 | 0/10 | 0/10 |
| ASPIRE | 2/5 | 0/10 | 1/10 |
| AGP | 5/5 | 8/10 | 10/10 |

这些结果支持 AGP 在这组三项真实任务上的优势。作者将部分差距归因于接触、摩擦、光照与深度噪声等仿真到真实差异，以及运行时反馈的作用；实验并未单独隔离每一种因素的因果贡献。（论文 §4.2.3、表 3）

### 5.3 “更快、更便宜”要先定义从什么时候开始算

| 任务 | ASPIRE：仅实际执行，分钟 / 美元 | ASPIRE：开发适配 + 执行，分钟 / 美元 | AGP：运行时执行，分钟 / 美元 |
| --- | ---: | ---: | ---: |
| 两对装配 | 2.9 / 0.00 | 64.8 / 18.90 | 9.2 / 4.47 |
| 金字塔 | 9.2 / 0.00 | 271.7 / 78.13 | 21.6 / 11.69 |

ASPIRE 的 real only 只看已生成程序的实际运行，期间没有进一步的 coding model 推理，因此该项推理费用为 0。sim + real 则把整套共享的仿真构造、调试及真机适配开销，**全额加到每个成功运行上，没有按复用次数摊销**。监督者对话、硬件准备和本地感知服务计算也不在这份账内。

这解释了为什么已准备好的 ASPIRE 程序实际运行更快，而加入未摊销的开发适配开销后 AGP 更省时。若反复执行同一套程序，摊销会改变比较结果，不能直接把表中倍数当作长期生产部署的成本优势。

还要注意，ASPIRE 金字塔的 1/10 包含适配过程中的一次成功，**不是冻结最终程序后另做十次独立评估**。GaP 没有成功试次，其成功运行均时、均费未定义。（附录 J）

## 六、经验保存在文件里，下一次执行再使用

### 6.1 保存的是程序和操作经验

AGP 可以在执行后保留测量值、成功抓取与插入参数、失败修正经验及脚本。后续会话读取这些文件，重新定位当前物体，再复用或修改已有程序；模型权重始终不变。

论文展示的文件包括 `memory.json` 和 `operate.py`。有些经验是可复用的尺寸或操作顺序，有些则是具体位置下的参数；后者需要结合新图像更新。例如，继承插入步骤时仍要重新计算物体的当前 XY 坐标，不能把上一次坐标原封不动地当成新场景真值。（论文 §4.3、附录 D）

### 6.3 将冻结经验从 Astra 交给 Terra

迁移实验先用 Astra 的五次两对装配形成经验，再将同一份冻结文件交给 Terra 的每个试次。Terra 不继续更新这些经验。

| Terra 条件 | 成功数 / 总数 | 成功均时 | 成功平均 Tokens |
| --- | ---: | ---: | ---: |
| 无经验 | 1/5 | 19.0 分钟 | 6.28 百万 |
| 使用 Astra 经验 | 4/5 | 12.5 分钟 | 5.56 百万 |

按作者口径，成功均时下降约 34.3%，token 用量下降约 11.4%。但这是**一个成功样本与四个成功样本**之间的条件均值比较，不能解释为每个试次都稳定提速。（论文 §4.3、附录 D.3）

失败案例也暴露了经验的适用条件：接收件位于接近工作空间内边界的位置，目标请求先被拒绝；Agent 为满足边界而偏移插入点，却改变了与真实零件的对齐关系，后续恢复未成功。保存下来的动作顺序无法自动解决新场景中的可达性问题。（附录 F.4）

### 7.1 一次四对装配中的在线修正

**原论文图 3：装配失败后的恢复**。一个包含最终验证和报告的 48.6 分钟会话中，Agent 多次修改抓取与插入方式；图中的时间分解属于这个具体案例。

这段执行先尝试将管子竖起，释放后管子倒下；随后把夹爪倾斜约 15° 重新抓取，再降低、释放并撤开，验证管子能够独立站稳。插入阶段，Agent 又裁剪放大局部图像，以小步下降和新观测逐步确认对齐。（论文 §4.4）

这里值得关注的是修正发生的层级：抓取方式、物体姿态、目标坐标和检查方法都能改变。恢复能力不只来自“再试一次”，还来自能够判断原来哪一部分操作条件不成立。

附录同时记录了失败试次：毛巾角在运输中滑脱，重新抓取又使整块布平移或旋转；另一次虽然执行完计划动作，仍有角没有折进去，Agent 却描述为已经完成。执行了预定顺序、得到紧凑外形，与真正满足所有层和角的目标关系，仍有差别。（附录 F.5）

| 失败现象 | 论文记录揭示的限制 |
| --- | --- |
| 六层塔在撤臂时倒塌 | 放开后站立不足以判成功，还要检查撤臂稳定性；散落方块超出可达范围后可能无法恢复 |
| 销与管发生暂时啮合，随后掉落或倾倒 | 夹持状态下的接触不等于稳定装配，需要重新检查抓取与支撑关系 |
| 继承的插入程序遇到工作空间边界 | 改动作目标以满足接口约束，可能同时破坏物体对齐 |
| 毛巾保留未折角却被宣告完成 | 操作误差之外还存在视觉验证误差 |
| 物体最终进入碗，但曾先撞桌面且碗被移动 | 最终落点正确不等于满足直接投掷和固定目标的任务要求 |

这些案例的机械成因并非全部被独立测定。例如塔倒塌的具体接触原因、布料滑脱中摩擦与张力各自的贡献，论文都没有完全隔离。可以讨论记录中发生了什么，但不应把事后解释写成已经证明的物理因果。（附录 F）

## 八、如何理解它与现有机器人策略的关系？

**我的理解**：AGP 展示了一种将通用模型能力接入机器人执行现场的方式。模型负责把视觉、几何程序、任务约束和失败反馈组织成下一步决定；底层控制器承担运动执行。它对开放式原型任务很有启发，因为临场发现的问题可以通过新的程序和动作继续处理。

与 [Harness VLA](Harness-VLA-paper.md) 对照阅读会更清楚：后者把冻结 VLA 作为高层可调用的局部操作原语；AGP 这篇论文重点展示通用 Agent 通过几何计算和机器人动作接口完成任务。两者都需要高层反馈与结果检查，但底层操作能力的来源和接口粒度不同。

这份证据仍有几条明确边界：

1. **不是实时高吞吐控制的验证。** 多项任务完成时间为几十分钟，观察与推理占据大量时间。
2. **不是广泛开放环境的成功率保证。** 主结果来自八种桌面配置，每种只有 5 或 10 次试验，并使用预先准备的接口、标定、参考材料和预算。
3. **不是经验迁移的完整因果结论。** 重复执行没有逐轮空经验对照，迁移资源均值又来自少量、不等数量的成功样本。
4. **换本体目前主要是定性案例。** 附录展示 P7 七轴臂配 RealHand L6 灵巧手抓住瓶子并提升 2 cm，没有报告同等规模的跨本体成功率评测。
5. **动作限制不等于完整安全保证。** 论文在运行时施加运动和工作空间约束，但面向人或陌生环境的部署仍需要独立防护与额外评估。

作者还提出，可以用 AGP 的执行记录收集机器人轨迹，支持后续策略学习；这在论文中是潜在应用。轨迹质量、收集成本，以及用这些数据训练出的策略表现，还需要进一步实验验证。（附录 G、H）

对我而言，最有价值的后续问题是：哪些临场推理值得保留，哪些重复步骤可以沉淀成可靠程序，以及何时应该把高频接触动作交给更专门的策略。AGP 的实验提供了具体的运行记录，也让这些效率与可靠性问题变得可以逐项检查。

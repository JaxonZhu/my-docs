# SCIZOR 论文解读：面向大规模模仿学习的细粒度数据筛选

论文原题：SCIZOR: A Self-Supervised Approach to Data Curation for Large-Scale Imitation Learning

- 作者：Yu Zhang、Yuqi Xie、Huihan Liu、Rutav Shah、Michael Wan、Linxi Fan、Yuke Zhu
- 机构：The University of Texas at Austin、NVIDIA Research
- 版本：arXiv 初稿发表于 2025 年 5 月；本文依据 2025 年 9 月 9 日的 v2
- 发表：官方项目页列为 ICRA 2026 Oral
- 论文：[arXiv:2505.22626v2](https://arxiv.org/abs/2505.22626v2)
- 项目：[SCIZOR 官方项目页](https://ut-austin-rpl.github.io/SCIZOR/)
- 代码：[UT-Austin-RPL/SCIZOR](https://github.com/UT-Austin-RPL/SCIZOR)

SCIZOR 关注一个容易被数据规模掩盖的问题：一条演示轨迹里，顺利操作、抓取失败、迟滞与无效重复可能交替出现。整条保留会让策略学到错误行为，整条删除又会丢掉有价值的片段。作者因此将数据筛选细化到 state–action / transition 层面，用任务进度估计识别低质量片段，用联合状态与动作表征识别重复片段。

:::{note}
正文由原始主笔记整理，并对照保存的原论文 v2 核对公式、实验表格与附录。文中的“我的理解”用于区分解释与论文结论；关于实现未披露的说明仅针对这份论文，本文没有进行训练代码复核。论文和项目链接也便于继续查阅后续版本。
:::

:::{important}
**核心观点**：数据治理不必只选择“哪个数据集”或“哪条轨迹”。SCIZOR 尝试保留一条轨迹中有用的部分，过滤缺乏有效进展或过度重复的部分。作者报告，在三类基准上相对不筛选数据平均提高约 **15.4 个百分点**的策略成功率；这是绝对成功率增益，不是相对提升 15.4%。
:::

## 一、为什么需要 transition 级别的数据治理？

### 1.1 数据更多，不代表每段监督都更好

大规模机器人演示通常来自不同机构、硬件、遥操作系统和操作者。数据规模扩大时，质量差异也随之扩大：操作员可能抓空、碰撞、停顿，某些容易采集的动作又可能大量重复。这些样本会改变训练分布，使稀有但有信息量的动作在采样中被淹没。

原笔记中关注的两个问题，可以分别对应到 SCIZOR 的两个模块：

| 数据问题 | 可能影响 | SCIZOR 的处理方向 |
| --- | --- | --- |
| Suboptimal：片段执行低效或失败 | 给策略提供不理想的行为监督 | 根据预测任务进度识别可疑片段 |
| Redundant：相似状态与动作被过度重复 | 高频模式占用过多训练权重 | 在联合表征空间中筛除近重复片段 |

这里的“低质量”是筛选方法给出的判断，并不意味着所有失败轨迹都没有学习价值。例如，失败后的恢复动作仍可能提供重要监督。

### 1.2 为什么不直接删掉整条轨迹？

已有机器人数据治理方法涉及不同粒度。数据集级方法调整不同来源的采样权重；轨迹级方法给整条 demonstration 评分。这些做法可以控制总体分布，却容易忽略同一条轨迹内部的质量变化。

**我的理解**：如果一条示范大部分操作流畅，只在抓取前停顿了一段时间，整条删除的代价很大；如果一条整体较差的轨迹包含一次有效恢复，只看总体分数也可能错过它。因此，作者希望只移除没有充分信息或可能提供错误监督的部分。

作者将 SCIZOR 定位为可扩展至 Open-X-Embodiment 规模的自监督、transition 级数据治理框架。“自监督”指评分器不需要额外的人工质量或任务进度标注；原始示范仍包含观测和动作，不能理解成策略训练完全不需要监督。

### 1.3 它改变的是训练数据

论文以模仿学习为背景，策略通过最大化示范动作的条件对数似然进行训练：

```{math}
\theta^* = \arg\max_\theta
\mathbb{E}_{(s,a)\sim\mathcal{D}_{\mathrm{expert}}}
\left[\log\pi_\theta(a\mid s)\right].
```

SCIZOR 的直接目标是整理示范数据 $\mathcal{D}_{\mathrm{expert}}$，再交给 BC、BC-Transformer 或 Octo 等策略学习算法。它没有把上述模仿学习目标替换为一个新的强化学习目标。（来源：论文 §3.1）

```{figure} images/SCIZOR/scizor-architecture.png
:width: 100%
:align: center

**原论文图 2：SCIZOR 架构**。左侧根据任务进度识别 suboptimal transitions；右侧根据状态与动作的联合表征去重。最终保留同时通过两个模块的数据。
```

流程可以拆成三个阶段：

1. **训练进度预测器**：从观测对之间的真实时间间隔构造自监督标签，学习常见示范中的时间与状态变化关系。
2. **生成两类筛选结果**：低质量模块给 transition 打分；按附录所述实验流程，去掉低质量片段后，再对剩余数据进行联合状态与动作表征的聚类和相似度去重。
3. **筛选训练样本并训练策略**：只保留同时满足质量与去重条件的数据，使用原有模仿学习算法训练。

论文图 2 表达的是两类保留条件的交集；附录 B.2 进一步说明实验执行顺序：先训练进度预测器并过滤低质量片段，再对剩余数据去重，最后训练策略。若用 $m_i^{\mathrm{sub}}$、$m_i^{\mathrm{dedup}}$ 表示两个保留 mask，则最终保留条件可以写为：

```{math}
m_i = m_i^{\mathrm{sub}}\land m_i^{\mathrm{dedup}}.
```

:::{note}
**筛选训练样本不等于把时间序列剪断后重新拼接**。附录 A.6 说明，对于 observation history 或 action chunking，作者先构造带历史和动作序列的样本，再做筛选，避免删除中间帧造成时间上的不连续。去重也以训练 mask 的形式过滤样本，不必物理删除原始文件。
:::

## 三、低质量筛选：用任务进度判断片段是否落后

### 3.1 真实时间是任务进度的代理标签

作者的出发点是：在多数有效演示中，任务应随时间向完成方向推进。真实机器人数据通常没有精确的进度标签，于是使用两次观测之间实际经过的时间，作为任务进度的代理监督。

设一个片段实际持续 $\Delta$ 秒，模型从片段的起止状态预测进度 $T_p$，用秒作为度量。论文将片段的 suboptimality score 定义为：

```{math}
u = \Delta - T_p.
```

如果实际经过两秒，而模型认为观测变化更像正常示范中较短时间内能完成的进展，那么该片段就存在“落后于预期”的迹象。分数越大，越值得怀疑。

**我的理解**：这是学习示范数据中的时间进展规律，再寻找偏离该规律的片段。它没有真实任务进度标签，因此不能直接保证预测值就是任务完成度，更不能简单理解成“画面变化越大，任务完成得越多”。成功状态相似、必要停顿或重复操作都会挑战这个代理指标。

### 3.2 模型结构：首尾帧、特征差分与时间区间分类

附录 A.2 给出的结构如下：

1. 用冻结的 **DINOv2** 分别编码片段的首帧与末帧。这里是对两个输入分别编码，不应据此理解为训练两个独立的视觉骨干。
2. 计算两份视觉特征的差值，突出变化、减少静态信息的干扰。
3. 将差分特征与 **CLS token** 拼接，输入多层 self-attention Transformer blocks。
4. 用输出 CLS token 经过分类头，预测时间区间，即 progress bin。

作者采用离散时间区间分类，而不是直接回归连续进度。附录 A.5 列出的五个区间为：

```{math}
[0,0.5),\quad [0.5,1.0),\quad [1.0,2.0),\quad
[2.0,5.0),\quad [5.0,+\infty),
```

单位均为秒。训练时按所选时间 bin 采样时间间隔 $\Delta t$，将间隔对应的观测对作为输入，预测其所属 bin。

:::{note}
**原文中的两处细节需要区分**。附录 A.3 称“五个等长时间 bin”，但 A.5 明确列出的是上述不等长区间；这里按具体边界展示，并保留这一表述差异。另一个容易混淆的地方是 **2 秒窗口**：附录 A.4 将它用于进度评分与状态动作特征提取，不意味着所有训练观测对都相隔两秒。

论文没有完整说明分类输出如何映射为连续 $T_p$，也没有完整交代最终评分的归一化。因此，下面公式用于解释论文的计算思路，不能仅据这些公式复原精确实现。
:::

### 3.3 从片段分数到每个 transition：三个步骤

片段评分还不足以直接进行细粒度筛选。SCIZOR 将重叠窗口证据、未来低质量证据与轨迹整体质量结合，得到每个 transition 的最终分数。（来源：论文 §3.2）

为避免原文将 $T$ 同时用于时间窗口和轨迹终点，下面使用不同符号重述计算思路：$\Delta$ 表示窗口持续的秒数，$H$ 表示窗口中的 transition 数，$L$ 表示一条轨迹的 transition 总数，下标从 0 开始。相同的两秒窗口在不同控制频率下可以对应不同的 $H$。

#### 第一步：汇集重叠子轨迹的证据

同一个 transition 可能属于多个重叠窗口。如果这些窗口都显示进度落后，那么该 transition 也更可疑。

用 $u_j=\Delta-T_{p,j}$ 表示起始于 $j$ 的片段分数。每个片段把分数均分给其包含的 $H$ 个 transition，再在当前 transition 处累加：

```{math}
\widehat V_i =
\sum_{j\in\mathcal{W}_i}\frac{u_j}{H},
\qquad
\mathcal{W}_i=\{j:\;j\leq i<j+H,\;0\leq j\leq L-H\}.
```

这更准确地说是“片段分数分摊后累加”。轨迹内部的 transition 在完整滑窗下通常由 $H$ 个窗口覆盖，此时也可以理解成这些窗口分数的平均；边界处的有效窗口更少，不能不加区分地称为普通均值。原文的含端点求和与 $1/T$ 分母也存在索引歧义，这里用集合写清覆盖关系。

#### 第二步：把未来的低质量证据向前传播

当前动作可能暂时看不出问题，却把机器人带到稍后会碰撞或停滞的状态。作者加入时间折扣，让未来的低质量证据影响较早的 transition，距离越远，影响越小：

```{math}
V_i = \sum_{t=i}^{L-1}\gamma^{t-i}\widehat V_t,
\qquad \gamma\in[0,1].
```

**我的理解**：这借用了折扣累积的形式。下一步就出现异常，比很久之后才出现异常，对当前分数的影响更直接。不过，沿时间回传分数是启发式的关联分配，不能据此证明当前动作在因果上导致了未来失败。论文未给出 $\gamma$ 的具体取值。

#### 第三步：混合局部分数与整条轨迹的质量

某些轨迹整体都存在频繁迟滞、抖动或失败。为了兼顾局部片段与整体示范水平，作者将当前 transition 的分数与全轨迹平均分混合：

```{math}
V_i^{\mathrm{final}} =
\alpha V_i + (1-\alpha)\frac{1}{L}\sum_{j=0}^{L-1}V_j.
```

附录给出 $\alpha=0.5$，即局部与全局两部分各占一半。最后，超过低质量阈值 $\epsilon_s$ 的样本被过滤。

这也揭示了方法的取舍：虽然最终 mask 作用到 transition，分数仍受整条轨迹影响。它并不是完全独立地判断每一步，也不保证保留低质量轨迹中的每一个有效动作。

## 四、重复筛选：在联合状态与动作空间中去重

### 4.1 为什么需要同时看状态和动作？

两个片段可能在视觉上很相似，实际动作却不同；也可能执行了相似动作，但对应完全不同的场景。只看图像或只看动作，都不足以判断两段机器人经验是否重复。

SCIZOR 因此把视频表征与动作序列拼接，以联合表征进行聚类和相似度比较。（来源：论文 §3.3；附录 A.7）

### 4.2 固定时长、均匀采样与视频编码

去重模块把每条完整轨迹切成固定时长、互不重叠的子轨迹。它和低质量评分中的重叠窗口不同：这里每个 chunk 是一个独立的去重比较单位。

具体处理为：

1. 按固定两秒切分 chunk，保持不同数据来源的时间跨度一致。
2. 从每个 chunk 均匀采样 **8 张 RGB 图像**，避免不同帧率直接造成输入帧数不同。
3. 使用预训练的 **Cosmos video encoder**，将视频压缩为一维特征向量 $z_v$。
4. 将视频特征与对应动作序列拼接，得到 $z_{v+a}$。论文描述的动作表示为末端执行器位姿增量，即 delta end-effector pose。

用示意式表达：

```{math}
z_{v+a}=\operatorname{concat}\!\left(z_v,\operatorname{vec}(a_{\mathrm{chunk}})\right).
```

这里的拼接式用于说明联合表征，不额外假定论文未说明的特征缩放或动作归一化方案。固定时间长度与固定视频帧数，也不意味着不同机器人动作空间天然就完全可比；OXE 实验另有动作空间统一步骤。

### 4.3 K-means 聚类后，只在同一 cluster 内比较

作者先对联合表征运行 K-means，将语义相近的 chunk 聚到一起，再在**同一 cluster 内**计算 chunk 两两之间的余弦关系。这里不是“与其他类中的 chunk 比较”。

设 $\mathcal{C}(x)$ 为 chunk $x$ 所属的簇。为了统一原文对“距离”和“相似度”的混用，可以写成：

```{math}
\begin{aligned}
d_{\min}(x)
&=\min_{\substack{y\in\mathcal{C}(x)\\y\ne x}}
\left(1-\cos(z_x,z_y)\right),\\
s_{\max}(x)&=1-d_{\min}(x).
\end{aligned}
```

最小余弦距离越小，说明存在一个越相似的邻居；等价地，最大余弦相似度越高，越可能重复。相似度阈值条件 $s_{\max}(x)>\epsilon_d$，对应距离条件 $d_{\min}(x)<1-\epsilon_d$。

:::{note}
论文先将最小距离称为 similarity score，随后又用最大相似度超过阈值描述删除条件。上式明确了两种口径的对应关系，但不是额外补充一种去重实现。原文没有完整交代重复组内的排序、代表样本保留方式或单元素簇处理规则，不能把“存在相似邻居”直接扩展成“重复组里的所有 chunk 都删除”。
:::

## 五、统一阈值如何选？为什么删除比例不同？

### 5.1 先看删多少，再看阈值对应多少

作者先在 RoboMimic 与 OXE Magic Soup 上分别运行两个单独模块，比较不同删除比例对应的策略成功率。

```{figure} images/SCIZOR/scizor-curation-ratio.png
:alt: RoboMimic 与 Open-X-Embodiment 上仅去除低质量样本和仅去重时，删除比例与策略成功率的关系
:width: 100%
:align: center

**原论文图 5：删除比例与策略效果**。图来自原笔记保存的配图；两个数据集对低质量筛选和去重的敏感程度不同，增加删除量不保证继续提高成功率。
```

在这些离散测试点上，作者总结的较优删除比例为：

| 模块 | RoboMimic | OXE Magic |
| --- | ---: | ---: |
| 仅去除 suboptimal | 约 30% | 约 10% |
| 仅去重 | 约 0% | 约 20% |

接着，作者根据分数分布考察阈值与删除比例的对应关系，选定统一阈值：

```{math}
\epsilon_s=0.58,\qquad \epsilon_d=0.99.
```

这两个阈值在 RoboMimic 和 OXE Magic 上选定，再直接用于 Sirius-Fleet 真机数据，没有为 Sirius-Fleet 单独重新搜索阈值。（来源：附录 A.1）

### 5.2 同一阈值不等于同一删除比例

下表按论文 Table 3 整理：

| 数据集 | Suboptimal 删除率 | 去重删除率 | 总删除率 |
| --- | ---: | ---: | ---: |
| RoboMimic | 29.3% | 0.3% | 29.6% |
| Sirius-Fleet | 4.7% | 3.2% | 7.9% |
| OXE Magic | 11.9% | 4.5% | 15.8% |
| OXE RT-X | 15.0% | 0.8% | 15.8% |
| OXE RT-1 | 9.2% | 0.5% | 9.7% |

总删除率按 Table 3 直接报告，不据前两列重新相加。例如，OXE Magic 的总删除率为 15.8%，小于 11.9% 与 4.5% 的和。原文没有完整解释这处差额的统计口径，因此不能直接断言它来自两个 mask 的重叠比例。

统一阈值也没有精确复现所有单模块的较优删除比例：OXE Magic 的去重删除率为 4.5%，不是图 5 中测试的 20%。作者将这一选择作为跨数据集使用的折中，而不是每个数据集、每个模块各自的最优点。附录文字与 Table 3 对 RoboMimic 的 suboptimal 删除率还有 29.5% / 29.3% 的小幅差异，这里统一采用表格值。

**我的理解**：删除率首先反映该评分器在当前数据上的判断，不能直接视为数据集真实质量的客观排名。这些实验支持阈值在所测试数据间具有一定迁移能力，还不足以说明新任务、新 embodiment 上无需验证即可使用。

过度去重的负收益也值得保留。它可能删掉有用的细微变化、降低有效样本数，或改变训练分布；但曲线本身没有单独证明性能下降一定由过拟合造成。

## 六、实验：更少的数据是否带来更好的策略？

### 6.1 三类数据，三种质量问题

| 数据设置 | 策略 | 主要检验的问题 |
| --- | --- | --- |
| OXE Magic Soup | Octo-Small | 大规模、多来源数据上的可扩展性 |
| RoboMimic Multi-Human | BC | 不同熟练度的人类演示能否有效筛选 |
| Sirius-Fleet | BC-Transformer | 自主策略与人工纠错混合数据中的局部质量变化 |

OXE 实验沿用 Octo 的 **Magic Soup** 数据混合权重，并在 SIMPLER 的 Pick Coke Can、Move Near 两项任务上评估。“Magic Soup”在这里指既有的数据混合配方，不能理解为 SCIZOR 对所有 OXE 子集重新设计了权重。论文还使用 OXE RT-X 配方比较 Re-Mix，使用 OXE RT-1 做评分机制消融。

RoboMimic 使用混合熟练度的 Multi-Human 数据，包含 Can 与 Square 任务；Sirius-Fleet 使用带人工干预的 1,500 条策略轨迹，真机评估包含四组、共八项任务。OXE Magic 与 RT-X 使用两个训练随机种子，RoboMimic 和 Sirius-Fleet 使用三个。（来源：论文 §4.1；附录 B.1–B.2）

### 6.2 基线分别在控制什么？

- **No Deletion**：使用未筛选的数据，检验筛选整体是否有收益。
- **Uniform / Random Deletion**：随机删除同等比例的数据，控制训练数据量，区分“删得更少”与“删对了样本”。
- **DemInf**：轨迹级筛选，用状态和动作之间的互信息估计轨迹质量，再移除低质量轨迹。
- **Re-Mix**：数据集级筛选思路，为 OXE RT-X 学习数据混合权重。SCIZOR 在对应 RT-X 设置训练 Octo-Small，Re-Mix 使用其已学习的混合权重。

这里统一使用 **DemInf** 的拼写；原论文不同位置出现 DemoInf、Deminf 等写法，指向同一比较方法。

- **RoboMimic**：DemInf 为 65.1%，高于 SCIZOR 的 62.3%。作者认为该数据明确包含不同熟练度层次，轨迹级筛选在这里特别有效。

- **OXE RT-X**：SCIZOR 为 31.3%，Re-Mix 为 27.8%，相差 3.5 个百分点。该结果来自 RT-X 配方，不能与 Magic Soup 一列混为同一个实验。

### 6.4 两个模块组合为什么重要？

论文 Table 1 比较只去除低质量数据、只去重与完整方法。下表保留论文的均值与误差项，单位为成功率百分比：

| 方法 | RoboMimic | Sirius-Fleet | OXE Magic |
| --- | ---: | ---: | ---: |
| 仅去除 suboptimal | 60.9 ± 1.8 | 64.2 ± 2.6 | 25.3 ± 2.9 |
| 仅去重 | 48.3 ± 0.8 | 63.3 ± 6.9 | 22.1 ± 0.9 |

## 七、究竟删掉了哪些行为？误检与漏检是什么？

### 7.1 被识别的低质量行为具有语义

作者从 RoboMimic 和 Sirius-Fleet 中，各随机抽取 100 条至少包含一个预测低质量片段的 demonstration，再人工检查其中被标记的片段。论文 Figure 4 统计的类别包括：

| 类型 | 含义与直观例子 |
| --- | --- |
| Manipulation Failure | 抓取失败、物体意外掉落等操作错误 |
| Pause / Stalled | 片段中几乎没有运动，例如机械臂停在某处 |
| Stuck at Collision | 夹爪或被抓物体碰撞后卡住，例如书碰到收纳盒 |
| Lagging / Slow Motion | 相同上下文中明显慢于正常速度；人工定义不包含有意的谨慎慢动作 |
| Move Back and Forth | 对任务没有明确贡献的无效往返运动 |
| False Positive | 被方法标记，但人工判断有歧义或不明确属于低质量的片段 |

最主要的类别包括迟滞、操作失败和停滞。这说明筛选结果与有意义的行为模式相关，但上述类别来自人工事后归纳，进度模型本身没有被训练成一个显式的六类故障分类器。人工定义中排除“必要慢动作”，也不代表模型总能正确识别操作者意图。

### 7.2 误检：被标记不一定真的应该删除

Sirius-Fleet 的这批已标记片段中，作者将 5% 归为误检或歧义样本：3% 出现在演示结尾，往往包含任务完成后的重复 padding 帧；另 2% 出现在低质量停顿前的短片段。

这个比例的分母是被检查的预测低质量片段，不能解释成 SCIZOR 在整个数据集上的总体误检率。（来源：附录 B.4）

### 7.3 漏检：失败未必造成明显的进度滞后

在另一个人工标注的 25 个机器人失败案例集合中，SCIZOR 检出了 13 个。作者将漏检分为两类：

1. **失败后很快恢复**：例如第一次没有抓住，但马上重新抓取成功，整体没有形成明显的进度落后。
2. **失败模式在训练数据中普遍存在**：自监督模型可能把这种模式当成常见行为，无法将其识别为异常。

因此，漏检与上一节的 False Positive 是不同问题；“未被筛掉”也不一定等于“模型认为操作正确”。

### 7.4 是否会删掉专家动作与恢复行为？

作者从 Sirius-Fleet 的五项任务中抽取共 50 条完美专家示范，没有发现被预测为 suboptimal 的片段。对恢复行为的检查中，54% 被完整保留、31% 被部分保留、15% 被删除。（来源：附录 B.4）

这些结果提供了保留有效行为的证据，但仍属于有限样本检查，不能推出所有恢复动作都能保留。对模仿学习而言，如何减少无效停顿，又不损害必要的恢复、等待和谨慎操作，仍是核心取舍。

## 八、局限与阅读后的理解

### 8.1 联合表征仍然比较直接

当前去重方法将视频特征与动作序列直接拼接。作者认为可以进一步使用更有表达力的联合表示，改善状态和动作空间的整合。仅有视觉相似或动作数值相近，不一定意味着两段经验具有相同训练价值。（来源：论文 §6）

### 8.2 自监督依赖数据中的主流行为相对可靠

SCIZOR 依靠多数示范中的规律学习正常进展，隐含了示范中的大部分片段较为有效的假设。如果低质量行为占据主导，模型可能将其学成“正常”，从而出现前文提到的漏检。

这也意味着方法不会凭空知道正确行为是什么。作者提出，后续可以研究如何更好地利用低质量数据中仍有价值的片段，而不只是删除它们。

### 8.3 任务进度并不总是线性的

实际任务可能需要长时间等待、反复搅拌、缓慢接触或多次试探。时间持续经过，视觉状态却未必呈现单调、显著的变化。将进展与时间间隔关联，容易在这些场景下产生歧义。

作者提出的后续方向包括更长的历史输入、能表达子任务的层次化进度建模，以及同时描述短期与长期进展的多时间尺度模型。这些是论文讨论的改进方向，尚不是当前实验验证的功能。

### 8.4 我如何理解这项工作的贡献

我更关注 SCIZOR 将数据治理粒度下移的思路：一条轨迹既可以包含应当减少采样的片段，也可以包含应该保留的有效行为。进度预测器提供质量代理，联合表征提供重复性代理，最终作用到训练样本选择。

实验支持这种组合在异质、质量不均的数据中有价值，尤其是自主执行与人工纠错混合的 Sirius-Fleet。同时，RoboMimic 上 DemInf 更高的结果、过度去重的下降以及误检和漏检分析，都说明粒度更细并不自动等于更准确。评估筛选方法，仍应同时看策略效果、删除比例，以及恢复和少见行为是否被保留下来。

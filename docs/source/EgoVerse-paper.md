# EgoVerse 论文解读：协作数据采集与人机迁移

论文原题：EgoVerse: An Egocentric Human Dataset for Robot Learning from Around the World

- 作者：Ryan Punamiya、Simar Kareer（共同一作）、Zeyi Liu、Josh Citron 等
- 学术团队：Georgia Tech、Stanford、UC San Diego、ETH Zürich、MIT CSAIL
- 产业参与方：Meta Reality Labs Research、Mecka AI、Scale AI
- 论文：[arXiv:2604.07607](https://arxiv.org/abs/2604.07607)，2026 年 4 月 8 日首次提交，7 月 7 日更新 v2
- 项目：[EgoVerse](https://egoverse.ai/) · [官方代码](https://github.com/GaTech-RL2/EgoVerse) · [数据浏览器](https://partners.mecka.ai/egoverse)

EgoVerse 希望把分散在人、实验室和企业之间的第一人称操作数据，组织成能够持续接收贡献、统一处理和用于训练的数据基础设施。它同时开展跨实验室、跨机器人平台的研究，检验人类数据在什么条件下能够帮助机器人。

我最关注的是两条相互关联的思路：**上游尽量统一数据采集与经验表达，下游再处理具体机器人的构形差异；扩大数据规模时，要同时检验任务、场景和操作方式是否对齐。** 人类数据让采集不必围绕某一台机器人展开，但并没有消除运动学、传感器和执行策略之间的差异。

:::{note}
**阅读范围**：本文采用 [论文 v2](https://arxiv.org/html/2604.07607v2) 的数据与实验口径。EgoVerse 持续更新，官网当前统计可能与论文快照不同。论文主要用 EgoVerse-A 子集研究模仿学习中的人机联合训练，并未验证整个工业数据集用于通用 VLA 训练的效果。
:::

## 一、EgoVerse 要统一什么？

### 1.1 数据规模之外，还有持续协作的问题

第一人称视频能够覆盖丰富的场景、物体与操作方式，但要用于机器人策略学习，通常还需要知道手在三维空间里怎样运动、相机怎样移动，以及动作对应哪个任务阶段。

这与 [EgoVLA](EgoVLA-paper.md) 中对手部位姿和相机位姿的需求相通。EgoVerse 进一步关注的是：不同机构采用不同设备采集的数据，如何长期接入同一个系统，并支持可比较的实验？

论文的工作由三个部分构成：

1. **EgoVerse 数据集**：包含受控的学术数据和更广泛的工业数据。
2. **EgoDB 与采集工具**：统一上传、处理、索引、浏览与训练访问，另提供手机采集方案。
3. **跨实验室研究**：使用共享任务与评估协议，比较人类数据规模、场景多样性和示范者多样性的影响。

## 二、怎样采集有用且可比较的人类数据？

### 2.1 多种硬件，统一输出信号

EgoVerse-A 使用 **Project Aria Gen 1**。前向 RGB 相机提供策略学习的主视觉流，侧向相机与 IMU 支持跟踪和相机运动估计；MPS 负责相关处理。

工业伙伴采用定制的可穿戴设备，通常包含双目鱼眼 RGB 相机，并在设备支持时提供深度和惯性信息。不同设备的原始传感器配置可以不同，但最终都转换到统一表示。

手机方案则将 **iPhone 安装在头带上**，使用超广角相机以 **1080p、30 fps** 录制视频，再通过云端视觉跟踪恢复 6-DoF 头部运动，并估计每只手的 **21 个三维关键点**。（论文 §III-A、附录 §VIII-E）

统一数据至少包含第一人称视频、手部关键点和相机位姿。手机方案降低了采集硬件门槛，但输出格式一致并不自动意味着它与更完整的传感器系统具有相同的姿态估计精度。

### 2.2 六项旗舰任务作为跨实验室参照

为了让多样性具有可比较的基础，EgoVerse-A 规定共同的任务语义：

| 旗舰任务 | 操作内容 |
| --- | --- |
| object-in-container | 将物体放入容器、倒出，连续重复 |
| cup-on-saucer | 调整杯子姿态并放到杯碟上 |
| bag-grocery | 打开购物袋并装入物品 |
| fold-clothes | 对不同初始配置的 T 恤完成三段折叠 |
| scoop-granular | 舀取颗粒材料并转移到容器 |
| sort-utensils | 将餐具分类放入指定容器 |

数据采集以 **dataset unit** 组织，每个单元通常约 5 分钟，包含约 5–10 次示范。共同协议约束任务目标与基本质量，同时记录示范者、场景和物体集合，保留可追踪的差异。

在这种“有边界的多样性”下，每个实验室通常为每项任务覆盖 8–12 个场景；各实验室独立采购物体，带来形状、外观和材质变化。相同任务指令也不会消除人的差异：身高、姿态、动作速度和双手协调方式都会影响轨迹与第一人称视角。

### 2.3 大规模数据仍需要明确的操作规范

EgoVerse-I 强调操作密集的片段，并通过人工质检减少无效内容。采集者被要求在可行时保持双手可见、对同一子任务采用一致的策略，并尽量避免无必要的犹豫与反复修正。

这些约束让动作更容易成为监督信号，也意味着数据并非对日常行为毫无干预的记录。它面向的是可用于机器人学习的示范式操作。（论文 §III-E、附录 §VIII-D）

## 三、EgoDB 如何把分布式采集接入训练？

### 3.1 文件、索引和处理状态分开管理

EgoDB 将大文件存入 S3 支持的对象存储，把可查询的 metadata 注册到集中式 PostgreSQL 数据库。论文附录描述了上传后定时登记，以及夜间进行预处理、校验和索引更新的流程。

| 环节 | 主要职责 |
| --- | --- |
| 上传 | 接收 Aria 原始文件、机器人原始数据及配套 metadata |
| 数据库 | 按 task、lab、scene、embodiment 等字段查询数据 |
| 处理流水线 | 运行姿态处理、格式转换和可视化生成 |
| 状态回写 | 更新 processed_path、帧数、预览路径与处理错误 |
| Web 浏览 | 查看示范、检查标注与追踪数据增长 |
| 本地训练访问 | 同步筛选后的数据，再构造统一数据集 |

这样的分工让原始文件、处理结果和使用条件都可以被追踪。数据库中的一条记录不等于数据已经可以训练，还需要检查处理状态与实际产物。（论文 §III-C、附录 §VIII-F）

### 3.2 EgoVerseDataset 的论文设计

论文将 `EgoVerseDataset` 描述为统一的 PyTorch 数据访问接口：

1. 根据任务、实验室、场景和机器人等条件查询 SQL。
2. 选择具有 `processed_path` 的记录。
3. 使用 `s5cmd` 并行同步到本地缓存，避免重复下载已有数据。
4. 将每个 episode 构造成独立数据集对象，过滤构形不匹配的记录。
5. 按训练、验证或百分比采样设置组织数据，对下游暴露统一接口。

附录列出了 `train`、`valid`、`total` 和 `percent` 等模式。这里说明的是论文中的数据访问设计；实际使用应对照相应版本的仓库接口。

公开实现已经继续演进。例如，在本文核对的 [2026 年 9 月代码版本](https://github.com/GaTech-RL2/EgoVerse/blob/42817f5dd80117ddf35178a35df801e769c47690/egomimic/rldb/zarr/zarr_dataset_multi.py)中，这条通路由 `S3EpisodeResolver`、`ZarrDataset` 和 `MultiDataset` 分担，已处理数据字段为 `zarr_processed_path`。论文接口名称可以帮助理解设计，但不应直接当作当前版本的 API。

**我的理解**：对于持续更新的数据集，仅保存查询条件还不够。同一条查询在不同日期可能得到不同数据。要复现训练结果，还需要固定实际 episode 清单、数据处理版本、训练划分和归一化统计。自动同步减少手工管理，但不能单独保证实验快照不变。

## 五、人类与机器人数据怎样对齐？

### 5.1 将未来手部轨迹转换到当前相机系

人类头戴相机持续运动，未来手部姿态原本属于各自时刻的设备坐标系。设 $T_t^{\mathrm{device}}$ 表示从时刻 $t$ 的设备系到世界参考系的变换，论文采用：

$$
a_{t:t+k}^{H}
=\left[
\left(T_t^{\mathrm{device}}\right)^{-1}
T_{t+i}^{\mathrm{device}}p_{t+i}^{H}
\right]_{i=1}^{k}.
$$

其中 $p_{t+i}^{H}$ 表示在未来设备系中记录的手部姿态；位置可用齐次坐标表示。先乘未来设备位姿，得到世界系表示，再乘当前设备位姿的逆，转换到当前设备系。

这个过程补偿了坐标基准的运动。它并不会让人和机器人具有相同的运动学或操作能力，也不保证两种数据在视觉上完全一致。

### 5.2 相同序列长度，不同物理时长

由于人类动作与机器人遥操作速度不同，附录采用不同的时间窗口：

| 数据 | 截取动作窗口 | 重采样后的长度 |
| --- | ---: | ---: |
| 人类示范 | 1 秒 | $T=100$ |
| 机器人示范 | 1.5 秒 | $T=100$ |

位置采用线性插值，旋转采用 SLERP。对于以 Euler 角存储的姿态，应理解为对其表示的旋转进行球面插值，而不是把 Euler 三个分量当作普通位置直接处理。（附录 §VIII-G）

100 是训练中的轨迹采样点数，不等于两种平台都以 100 Hz 实时控制。重采样让动作序列更便于共同建模，也包含对不同执行速度的适配。

### 5.3 分位数归一化与视觉增强

论文分别对不同构形的本体状态和动作进行归一化，将每个特征的第 1、99 百分位映射为 $-1$ 和 $1$：

$$
\widehat x
=2\left(\frac{x-q_{0.01}}{q_{0.99}-q_{0.01}}\right)-1.
$$

这样可以降低极端值对尺度估计的影响。公式本身没有裁剪操作，落在这两个分位点之外的数值仍可能超出 $[-1,1]$。视觉输入还使用随机裁剪和 color jitter，减轻相机与外观差异。

## 六、联合训练策略：Stems、共享编码器与 Flow Matching

### 6.1 这里实验的是视觉模仿学习策略

本文使用 **ResNet-18 + Transformer + Flow Matching** 的策略结构。图像和本体状态进入模型，没有把语言编码器作为这组实验的输入，因此不宜直接称为语言条件 VLA。

EgoVerse-I 提供密集语言标注，意味着数据能够支持后续语言条件策略研究；这是数据能力与本文实验范围的区别。

### 6.2 每个 stem 如何产生 tokens？

视觉输入经 ResNet-18 得到 $7\times7\times512$ 特征图，再展开并线性投影。本体状态经线性层映射到特征空间。

每个 stem 使用 $L=16$ 个可学习 query，通过**一个包含 8 个注意力头的 cross-attention block**提取特征。“一个 block”不等于“单头注意力”。

若有 $m$ 个 stems，则得到 $mL$ 个 query tokens。再拼接 $M$ 个可学习 context tokens：

$$
N_{\mathrm{encoder\ input}}=M+mL.
$$

附录表 VII 的四分支配置包含主视角、两路腕部视角与本体状态，因此：

$$
m=4,\quad L=16,\quad M=64,\qquad M+mL=128.
$$

其中 64 个 context tokens 的编码结果用于为动作解码器提供条件。这是表中列出的机器人配置，不能机械地给没有腕部相机的人类数据也补出相同传感器分支。

| 模块 | 附录配置 |
| --- | --- |
| Stem 投影宽度 | 256 |
| 共享 Transformer encoder | 16 层、8 头、宽度 256，Pre-LN |
| Context tokens | 64 |
| Flow Matching decoder | 6 层、4 头、宽度 128 |
| 输出动作维度 | 按任务与构形设置 |

### 6.3 Flow Matching 的路径、目标与积分方向

设真实动作序列为 $a_1$，高斯噪声为 $a_0\sim\mathcal N(0,I)$。论文采用：

$$
\tau\sim\operatorname{Beta}(1.5,1.0),\qquad
x_\tau=\tau a_0+(1-\tau)a_1.
$$

此定义下，$\tau=1$ 是噪声，$\tau=0$ 是目标动作；对 $\tau$ 求导，目标速度为 $a_0-a_1$。每种构形的条件 Flow Matching 损失写为：

$$
\mathcal L_{\mathrm{CFM}}^{e}
=\mathbb E_{\tau,a_0,a_1,s}
\left[
\left\|
\pi_\theta(x_\tau,\tau,f_\phi(s))-(a_0-a_1)
\right\|_2^2
\right],
$$

$$
e\in\{\mathrm{human},\mathrm{robot}\}.
$$

两种数据共同优化：

$$
\mathcal L_{\mathrm{BC\text{-}cotrain}}
=\mathcal L_{\mathrm{CFM}}^{\mathrm{human}}
+\mathcal L_{\mathrm{CFM}}^{\mathrm{robot}}.
$$

解码器通过交替的 self-attention 与 cross-attention，将编码器输出的上下文注入动作序列。推理从高斯噪声开始，沿 $\tau:1\to0$ 做 **10 步 Euler 积分**。由于这里的时间方向从噪声端向目标端递减，不能只更换速度符号而保持其他定义不变。（附录 §VIII-I）

### 6.4 数据配比比“共同训练”四个字更具体

旗舰任务的联合训练使用：

- **EV 8h**：来自四个采集站点、与当前任务匹配的 EgoVerse-A 人类数据。
- **ID 2h**：专门在对应机器人数据的相同物体、任务配置和场景下采集的人类数据。
- **机器人示范**：对应任务与平台的数据，数量见前表。

人类样本从 EV 与 ID 的并集中均匀抽取，机器人样本从相应示范中按帧均匀抽取。旗舰与 scaling 实验每个 batch 共 32 个样本，其中 **16 个人类、16 个机器人**。

这里的 1:1 是人类与机器人的 batch 比例。EV 和 ID 在人类数据内部并不因此各占一半；并集均匀采样也不会自动让每个实验室、每个 episode 获得相同权重。

训练使用 AdamW，学习率和 weight decay 均为 $10^{-4}$，训练 150K steps。跨实验室的计算资源与训练时间不同，论文没有把它们统一成一个硬件预算。（附录 §VIII-I、J）

## 七、真实机器人实验应怎样读？

### 7.1 ID / OOD 的参照是机器人训练分布

每种方法、每项被评测任务执行 **20 次 ID + 20 次 OOD rollout**，随机化物体位置、方向、组合或初始状态。

ID 使用与机器人训练数据一致的任务布局和分布。OOD 则按任务改变物体、组合、桌面或环境；部分 OOD 物体在**人类数据**中出现过，只是没有出现在机器人数据中。因此，这些设置并不全部属于“对所有训练来源都未见过的物体”。

同理，ID 人类数据强调场景与任务对齐，但人和机器人仍在视角、传感器和动作执行上存在差异。不能把它描述为完全消除了 domain gap。

### 7.2 归一化分数不等于成功率

| 任务 | 主要计分方式 | 主报告指标 |
| --- | --- | --- |
| object-in-container | 40 秒内，每次成功放入与倒出各计 1 分 | Normalized score |
| bag-grocery | 开袋 1 分，三个物品按规定顺序装入各 1 分，最多 4 分 | Normalized score |
| cup-on-saucer | 记录拾取、交接和放置阶段；最终杯子正确放到杯碟上 | Success rate |
| fold-clothes | 记录三段折叠；全部完成才算任务成功 | Success rate |

Normalized score 按获得分数除以最大可能分数计算，用于统一对应任务的表现。由于不同平台的执行速度、复位范围和任务实现有差异，作者强调优先比较同一平台加入人类数据前后的变化，不宜直接按绝对分数给机器人平台排序。（附录 §VIII-J）

整体上，加入 EgoVerse-A 在多种平台和任务中改善了 ID 表现及 OOD 泛化，但不是每个组合都提高。Robot B 的 bag-grocery 在 ID 设置下出现明显退化，OOD 则基本持平；部分其他设置也持平或下降。

这是作者提出的解释，尚不是通过单独控制策略差异得到的因果证明。它提醒我：**语义对齐、场景对齐与动作策略对齐需要分别检查。**

## 八、扩大规模与增加多样性，分别带来什么？

### 8.1 少量对齐数据帮助利用更广泛的人类数据

Scaling 实验固定机器人数据，改变人类数据组成，包括 Robot-only、ID 1h、ID 2h、EV 8h，以及 EV 2h + ID 2h、EV 8h + ID 2h。

```{figure} images/EgoVerse/egoverse-domain-aligned-scaling.png
:alt: 在机器人数据固定时，比较仅加入对齐人类数据、仅加入多样人类数据以及二者组合的效果
:width: 100%
:align: center

**原论文图 10：对齐数据与规模扩展**。少量 ID 人类数据与多样 EV 数据组合后，产生更有效的迁移。
```

在这组实验中，单独加入 EV 8h，或只使用少量 ID 人类数据，都不足以稳定带来同等幅度的收益；两者组合后，多样人类数据的增量更容易转化为策略提升。

**我的理解**：ID 数据让模型有机会在接近机器人场景的条件下学习人机关系，再利用更多场景中的操作经验。这个结果支持本文训练配方中的对齐机制，但不能扩展为所有人机迁移方法都必须采用相同的 ID 数据配置。

### 8.2 把多样性拆成示范者与场景

自然汇集的跨实验室数据往往同时改变场景、物体、人数与时长，难以分辨收益来自哪里。作者另外为 cup-on-saucer 和 fold-clothes 构建受控子集，使用 16 名示范者与 16 个场景的采集池，开展四组研究：

| 设置 | 主要改变的因素 | 数据预算与评估 |
| --- | --- | --- |
| 单场景示范者扩展 | 1、2、4、8、16 名训练示范者 | 固定 2 小时；测试同场景中的留出示范者 |
| 多场景示范者扩展 | 4、8、12 名示范者 | 固定 8 个场景、8 小时；测试这些场景中的未见示范者 |
| 混合多样性 | 4–8 个场景，4 或 8 名示范者 | 固定 4 小时；测试未见场景与示范者 |
| 场景扩展 | 1、2、4、8、16 个场景 | 比较不同每场景数据用量；测试未见场景与示范者 |

前三组固定相应总时长。场景扩展实验的同一数据使用比例下，总时长会随场景数增加，因此读图时应同时检查场景数、每场景用量和总预算，不能把所有曲线都称为固定总时长实验。（附录表 VIII–XI）

### 8.3 Avg-MSE 是离线动作预测指标

给定预测轨迹 $\widehat a_{1:T}\in\mathbb R^{T\times D}$ 和真实轨迹 $a_{1:T}$，论文定义：

$$
\operatorname{Avg\text{-}MSE}
(\widehat a_{1:T},a_{1:T})
=\frac{1}{T}\sum_{t=1}^{T}
\frac{1}{D}\|\widehat a_t-a_t\|_2^2,
$$

再对验证 episodes 取平均。它评估的是人类数据上的开环动作预测，数值越小表示在该评价表示下预测误差越低。

原图纵轴标为 “Avg-MSE (m)”，但附录公式是平方误差，单位标注与公式之间存在歧义。这里保留指标名称用于相对比较，不将图中数值直接换算成厘米级的手腕位置误差。

### 8.4 场景覆盖收益较稳定，增加人数的作用依赖任务

固定单场景或多个已知场景时，增加示范者通常改善对未见人的动作预测；扩大场景覆盖则改善对新环境的预测。对 fold-clothes，场景扩展在低数据预算下尤其有帮助。

但人数收益并不处处单调。附录的 cup-on-saucer 混合多样性实验中，4 名示范者略优于 8 名，而 fold-clothes 中 8 名优于 4 名。作者推测约束更强的任务可能受到额外行为差异影响；这同样是对结果的解释，而不是已经验证的普遍规律。

这部分研究的边界很明确：**它只使用离线人类预测指标。** 模型在人类轨迹上预测得更准，仍可能因为机器人可达性、控制误差、碰撞或操作策略差异而执行失败。论文也将进一步机器人 rollout 验证列为后续工作。

## 九、我从这篇论文中得到的启发

### 9.1 采集系统应保留差异，而不是只追求统一文件格式

统一格式能够把多个来源送入同一训练代码，但实验还需要知道数据来自谁、在哪里、使用什么物体、按什么策略完成。示范者、场景和处理版本等 metadata，直接决定我们能否分析多样性和构造可靠的数据划分。

EgoVerse-A 的共同任务定义与受控子集，比单纯汇报更多小时更有研究价值：它们让“增加哪一种数据有效”成为可以检验的问题。

### 9.2 同一个任务名不保证动作能够迁移

Robot B 的装袋结果表明，平台能力会改变合理的操作方式。即使目标都叫“装购物袋”，人类双手策略和机器人夹爪策略仍可能相互冲突。

因此，我更倾向于把人机对齐看成几个层面共同满足：目标一致、场景相关、动作表示可转换，以及示范策略对目标机器人可执行。几何坐标对齐只解决其中一部分。

### 9.3 数据资源规模与论文验证范围需要分别判断

接下来值得追问的是：怎样利用弱对齐甚至未对齐的工业数据，怎样比较联合训练与先预训练再微调，以及离线多样性收益能否稳定转化为真实机器人表现。论文建立了可继续研究这些问题的数据和评估基础，但没有一次性回答所有问题。
